## Definition

Canonical-рівні складності:
- `L0` / `light`;
- `L1` / `balanced`;
- `L2` / `strong`;
- `L3` / `research/experimental`;
- `Lx` / `custom`.

## Assumptions

- Вміст рівнів уточнюється у майбутніх малих ТЗ етапів.
- Кожен основний етап має підтримувати щонайменше `L0`, `L1`, `L2`, якщо інше
  не буде явно зафіксовано у специфікації етапу.

## Theorem / Contract

Для кожного етапу рівень складності визначає:
- сімейство алгоритмів;
- дозволені реалізації;
- діапазони параметрів;
- дозволені домени даних;
- очікуваний час виконання;
- частку кадрового time budget;
- очікуваний вплив на якість;
- обмеження.

Canonical-семантика рівнів:
- `L0` / `light` - мінімальна обчислювальна вартість, орієнтація на жорсткий
  real-time профіль `RT-5`, тільки прості однопрохідні або майже однопрохідні
  варіанти.
- `L1` / `balanced` - базовий збалансований режим, компроміс швидкості та
  якості.
- `L2` / `strong` - підвищена якість за рахунок більшої обчислювальної
  вартості.
- `L3` / `research/experimental` - дорогі або експериментальні алгоритми, не
  обов’язкові для першої canonical-реалізації.
- `Lx` / `custom` - спеціалізовані профілі під конкретний сценарій із явною
  валідацією.

Рівень складності входить до конфігурації `C` і обмежує допустиме значення
`variant` для етапу.

## Interpretation

Рівень складності є керованим виміром продукту, а не неформальною підказкою щодо продуктивності.

## Failure cases

- `fast` behavior без задекларованих обмежень домену даних і якості.
- Використання stateful-моделі у `RT-5` без доведеної продуктивності.
- Вибір `variant`, який не належить до задекларованого рівня.

## Typical misuse

- Використовувати `Lx` як escape hatch без валідації.
- Називати режим `L0`, але виконувати дорогі багатопрохідні операції.

## Open questions

- Бюджет часу виконання для кожного етапу.
- Метрики якості для кожного рівня.
- Формальна таблиця сумісності `profile -> level -> variant`.
