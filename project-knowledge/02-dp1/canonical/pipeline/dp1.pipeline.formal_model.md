## Definition

Canonical-конвеєр DP1:

```text
Π = <E1, E2, ..., EK>
```

Кожен `Ei` є інтерфейсом етапу.

## Assumptions

- Кожен етап має одну або більше реалізацій `V_i,j`.
- Canonical-конвеєр виявлення містить вісім основних етапів: `Prep`,
  `Radiometric correction`, `Enhancement/denoising`, `Matched filtering`,
  `Candidate extraction`, `Segmentation refinement`, `Object filtering`,
  `Measurement`.
- Інфраструктурні етапи у цьому наборі карток інтерфейсів не описуються.

## Theorem / Contract

Кожна реалізація `V_i,j` визначається через:
- сімейство алгоритмів;
- набір параметрів;
- допустимі вхідні домени даних;
- внутрішній домен обчислень;
- вихідні домени даних;
- обчислювальну вартість;
- очікуваний вплив на якість виявлення та вимірювання;
- відповідність OpenCV (`native`, `wrapped`, `composed`, `custom`);
- володіння станом, якщо використовується stateful-модель.

Конфігурація конвеєра:

```text
C = (V_1,j1, V_2,j2, ..., V_K,jK)
```

Час обробки кадру для конфігурації `C` моделюється як:

```text
T(C) = sum_i T_i(V_i,ji, P_i, N, K_i)
```

Де:
- `T_i` - час виконання `i`-го етапу;
- `V_i,ji` - вибрана реалізація етапу;
- `P_i` - набір параметрів етапу;
- `N` - розмір даних, наприклад кількість пікселів кадру або ROI;
- `K_i` - допоміжні параметри вартості етапу: розмір ядра, кількість tiles,
  кількість кандидатів, сегментів або фінальних об’єктів.

Виконання має фіксувати:
- час кожного етапу;
- сумарний час кадру;
- час явних перетворень форматів;
- кількість tiles;
- кількість кандидатів;
- кількість сегментів;
- кількість фінальних об’єктів.

## Interpretation

Конвеєр не є фіксованою legacy-послідовністю. Це конфігурований вибір реалізацій за формальними інтерфейсами етапів.

## Failure cases

- Порядок етапів є неявним.
- Вибір реалізації жорстко закодований поза конфігурацією `C`.
- Перетворення доменів даних приховано всередині етапу.
- Витрати на перетворення форматів не входять до часової моделі.
- Stateful-модель не має задекларованого власника або вартості.

## Typical misuse

- Трактувати реалізацію як контракт етапу.

## Open questions

- Повна схема для `C`.
- Точні бюджети часу для RT-профілів.
- Метрики якості для компромісу час/якість.
