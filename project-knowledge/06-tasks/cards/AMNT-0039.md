## Summary

Update the canonical validation checklist so future reviews can detect the
current failure mode: a stage output exists but is not reflected in
`FrameContext`.

## Goal

Make `FrameContext` artifact reflection reviewable.

## In scope

- Add checks for:
  - root input artifact exists after successful frame packet creation;
  - completed stage output has corresponding context artifact;
  - failed / unsupported stage does not register successful output artifact;
  - artifact domain matches `stage_io_matrix`;
  - non-root artifact has a parent artifact;
  - producer stage matches stable stage key;
  - profiling checks reference existing profiling policy and domain.

## Out of scope

- No automated tests.
- No test fixtures.
- No code changes.
- No new validation infrastructure.
- No full profiling implementation.

## User constraints

- Testing changes require separate approval.
- Keep this as checklist / knowledge update.

## Source access rules

Validation task. Legacy access is forbidden.

## Assumptions

- The first implementation slice will only register raw input and radiometric
  output artifacts.

## Result

Completed.

Updated `dp1.validation.stage_contract_checks` with checklist coverage for
`FrameContext.artifacts` reflection. The validation card now includes checks for
root `raw_frame` registration after successful `FramePacket` creation, completed
authoritative stage outputs having corresponding context artifacts, non-success
stage statuses not registering successful output artifacts, artifact domain and
provenance consistency with `dp1.pipeline.stage_io_matrix`, parent artifact
links, stable `producer_stage` identity, and ownership/lifetime semantics that
do not imply hidden heavy-buffer ownership.

Added a current-slice expectation for `raw_frame` and
`radiometric.processing_frame`, plus failure cases for missing reflection and
fake successful artifacts. Profiling-related checks remain references to
`PROFILING_POLICY.md` and `dp1.domain.profiling`; no profiling structures were
redefined.
