## Summary

Потрібно поставити на потік цикл розробки для ядра проєкту (DP1/DP2): зробити запуск і збірку відтворюваними, уніфікувати шляхи ресурсів, знизити поріг входу для нових розробників та синхронізувати knowledge base.

## Goal

Отримати стабільний командний workflow: після змін DP1/DP2 агент збирає debug/release, передає команди запуску та шляхи до ресурсів, а розробник може одразу запускати і дебажити на dataset-ах із єдиної директорії ресурсів.

## In scope

- Уніфікація резолву шляхів ресурсів у DP1/DP2 без прив'язки до конкретного користувача.
- Repo-first конфігурація шляху до ресурсів з fallback.
- Оновлення прикладних конфігів DP1/DP2 на універсальний формат шляхів.
- Документація командного workflow для debug/release і запуску DP1/DP2.
- Оновлення knowledge base по pipeline розробки.

## Out of scope

- Локальні admin-дії на конкретному сервері (створення директорій HDD, права доступу, Samba host/user/password, mount-політики).
- Широкі рефакторинги поза DP1/DP2.
- Зміни мережевих контрактів DP1<->DP2.
- Додавання нових бібліотек або тестової інфраструктури.

## User constraints

- Пріоритет тільки DP1/DP2 як ядра проєкту.
- Ресурси мають бути в одній базовій директорії на кшталт `AmanitaResources/...`.
- Поріг входу має бути мінімальним: не вимагати обов'язкового ручного створення env змінних.
- У task card фіксувати тільки командні зміни; локальні налаштування не включати.
- Оновити knowledge base щодо pipeline розробки.
- Кореневий `README.md` має бути повністю оновлений українською мовою з урахуванням нового workflow.

## Assumptions

- Для командного стандарту достатньо repo-first конфігурації + fallback до дефолтного шляху від кореня репозиторію.
- Env-змінна може існувати лише як optional override.
- Дефолтні конфіги DP1/DP2 можуть містити placeholders для ресурсних шляхів.

## Risks

- Некоректний резолв шляхів при нестандартному запуску бінарників.
- Регресія в запуску зі старими absolute-path config файлами.
- Розбіжність між документацією і фактичними build командами.

## Validation approach

- Локальна збірка DP1/DP2 у Debug і Release.
- Ручний smoke-run з перевіркою парсингу конфігів та резолву шляхів.
- Review змін документації на узгодженість із реальними командами.

## Execution notes

- Створено task card перед внесенням нетривіальних змін.
- Додано repo-first ресурсну конфігурацію через `amanita_resources.conf`.
- Для DP1/DP2 додано резолв плейсхолдера `${AMANITA_RESOURCES_DIR}` з fallback без обов'язкового env.
- Додано єдиний build-скрипт `builder/build_dp1_dp2.sh` для Debug/Release.
- Для стабільної конфігурації в наявному середовищі додано preload-залежностей `Eigen3` і `OpenEXR` через `CMAKE_PROJECT_INCLUDE`.
- Підтверджено локальну збірку DP1/DP2 у `Debug` і `Release`.
- Оновлено `README.md` та `PROJECT_ECOSYSTEM.md` розділами development pipeline.
- Додатково повністю переписано кореневий `README.md` українською мовою на основі попередньої структури з актуалізацією під DP1/DP2.

## Result

Виконано командні зміни для стандартизованого DP1/DP2 workflow:

- У default config файлах DP1/DP2 прибрано user-specific absolute paths, додано portable placeholder paths.
- Runtime DP1/DP2 тепер підтримує repo-first визначення кореня ресурсів без ручного створення env змінної.
- Додано уніфікований build-процес для `Debug`/`Release` з окремими build директоріями.
- Документовано запуск DP1/DP2, ресурсну структуру та handoff-формат для розробницького циклу.
- Кореневий `README.md` повністю синхронізовано з новим станом проєкту та україномовним стандартом документації.
- Зміни локального адміністрування хоста (Samba, права, каталоги HDD) не включались у task card.
