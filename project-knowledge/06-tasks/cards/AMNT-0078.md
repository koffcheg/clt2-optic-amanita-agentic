## Summary

Add the DP1 v2 tile executor for Task 6. The class name is `TileExecutor`, but
the implementation is oneTBB-only.

## Goal

Run pre-built `TileTask` objects through `TileProcessor` with oneTBB
tile-level parallelism and return a bounded execution summary.

## In scope

- Add `TileExecutionSummary`.
- Add `TileExecutor`.
- Execute tasks through `oneapi::tbb::parallel_for`.
- Respect `TileExecutionConfig::num_threads` with default oneTBB behavior for
  `0` and a local `task_arena` for positive values.
- Add focused unit-test coverage approved by the user.
- Update local build source lists.

## Out of scope

- Implementing `TilePipeline`.
- Aggregating frame-level results.
- Connecting tile execution to `process_single_frame`.
- Adding serial fallback or backend dispatch.
- Adding logging/profiling configuration fields.
- Changing full-frame behavior.

## User constraints

- Use the class name `TileExecutor`, not `OneTbbTileExecutor`.
- Use oneTBB as the only execution mechanism.
- Do not add `SerialTileExecutor`.
- Do not add `backend` to `tiles.execution`.
- Do not write to `FrameContext` from worker threads.
- Do not add per-tile logging.
- Unit tests are explicitly approved for this task.

## Source access rules

Canonical development only. Legacy access is forbidden.

## Assumptions

- `TileProcessor::process` is the current accepted tile-worker method name.
- `RadiometricStage` tile route may still return `Unsupported` for
  `inverse_median` until per-tile state ownership is implemented later.
