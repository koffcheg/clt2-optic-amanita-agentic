Review result:

- Canonical `FrameContext` is not metadata-only. It is defined as runtime
  context plus bounded artifact registry / provenance layer.
- Canonical `FrameContext` is not a mandatory heavy-buffer owner. The ownership
  policy and C++ implementation keep the registry metadata-only for this slice.
- Stage contract requires explicit outputs and `FrameContext.artifacts`
  reflection for successful authoritative outputs.
- Current C++ `FrameContext` has artifact registry metadata fields and no
  `cv::Mat`, pointers, references, `std::variant`, or stage-output storage in
  `FrameArtifactRef`.
- Current runtime registers `raw_frame` only on the successful packet path.
- Current runtime registers `radiometric.processing_frame` only when
  `RadiometricStage::process(...)` returns `StageExecutionStatus::Completed`.
- Failed or unsupported radiometric paths do not register a fake successful
  radiometric artifact.
- Existing radiometric stage comments align with the corrected contract.
- Profiling references follow the root profiling policy and profiling domain;
  the artifact registry is not used as a profiling storage model.
