## Summary

This task records the architecture decision and execution scope for reconciling
the current canonical DP1 and `datapro1_v2` `FrameContext` model with the Big TZ
requirement that `FrameContext` reflects frame data state.

The selected reconciliation is Variant B:

```text
FrameContext does not own heavy buffers by default.
FrameContext is the mandatory artifact registry / provenance / audit layer
for authoritative frame products that already exist in the current pipeline.
```

This task is intentionally a scope and decision task. It does not update
canonical domain cards and does not change code.

## Goal

Create a clear starting point for the narrow `FrameContext` correction series so
that a future agent understands:

- the exact problem;
- the chosen architecture direction;
- the files and materials that must be read;
- the work that is in scope;
- the work that is explicitly out of scope.

## In scope

- Define the problem as a mismatch between Big TZ `FrameContext` semantics and
  the current canonical / `dp1_v2` metadata-only tendency.
- Select Variant B as the approved direction for future tasks in this series.
- State that current stage outputs remain explicit.
- State that successful authoritative outputs must be reflected in
  `FrameContext`.
- State that `FrameContext` must not become a hidden owner of all heavy
  `cv::Mat` buffers.
- List all source materials that motivated the decision.
- List the subsequent task-card sequence `AMNT-0035` through `AMNT-0046`.

## Assumptions

- Big TZ section 10.3 is the source of the semantic concern: `FrameContext`
  should reflect raw frame, processing representations, masks, contours /
  components, objects, measurements, profiling, and configuration metadata.
- Current canonical DP1 currently describes `FrameContext` mostly as runtime
  metadata and explicitly rejects primary outputs in context.
- Current `datapro1_v2` code follows that explicit-output / metadata-context
  direction.
- The safest reconciliation is not to move all buffers into `FrameContext`, but
  to make `FrameContext` a registry of authoritative artifacts and provenance.
