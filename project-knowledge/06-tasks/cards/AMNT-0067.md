## Summary

Update the default DP1 v2 application config to a minimal logging/profiling surface and make removed fields optional in the JSON parser, while keeping the typed config model intact.

## Goal

Default JSON contains only required minimal logging/profiling fields; parser accepts configs missing removed fields and still validates explicit advanced values.

## In scope

- Simplify default logging/profiling blocks in application_config_datapro1_v2.json.
- Make logging.default_level optional in parsing.
- Make logging.sampling optional in parsing.
- Keep profiling.logging_bridge.summary_every_n_frames optional in parsing.
- Update unit tests to reflect minimal JSON and optional fields.
- Update runtime profiling summary trigger to use aggregation_window_frames only.
- Adjust runtime logging conditions for frame/window/run summaries.
- Update runtime profiling aggregator unit tests to match the new trigger logic.

## Out of scope

- Changes outside DP1 v2 runtime profiling/logging summary emission.
- New tests, fixtures, or test infrastructure.
- Changes to typed config structs or canonical config surface.

## User constraints

- Follow LOGGING_POLICY and PROFILING_POLICY.
- Follow canonical logging/profiling configuration cards.
- Do not remove typed config structs or canonical surface.
- Remove specified fields from default JSON.
- Keep advanced fields optional and validated when present.

- Minimal JSON should still parse with defaults applied.
