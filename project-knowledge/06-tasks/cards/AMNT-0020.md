## Summary

Create a governance logging policy and a canonical DP1 application
configuration card whose current scope is logging only.

## Goal

Document where logging behavior rules live, define the typed DP1 application
logging configuration surface, and keep application-runtime configuration
separate from pipeline configuration `C`.

## In scope

- Create `project-knowledge/00-governance/LOGGING_POLICY.md` in English.
- Create `project-knowledge/02-dp1/canonical/configuration/dp1.config.application.md`
  in Ukrainian, except template section names and technical identifiers.
- Add a minimal boundary statement to `dp1.config.pipeline_configuration_c.md`.
- Add the new application configuration card to `DP1_CANONICAL_INDEX.md`.
- Add this task card to `TASKS_INDEX.md`.

## Out of scope

- Legacy documents and legacy code.
- C++ source changes.
- Runtime JSON configuration files.
- log4cxx XML configuration files.
- Tests, fixtures, mocks, and validation artifacts.
- Other application-runtime configuration sections beyond logging.

## User constraints

- Do not analyze or use legacy information.
- `LOGGING_POLICY.md` must be written in English.
- `dp1.config.application.md` must be written strictly in Ukrainian except YAML
  keys, template section names, technical identifiers, paths, code snippets, and
  configuration field names.
- The application configuration card must describe only logging in this task.
- Avoid duplicating the application-vs-pipeline boundary in the logging policy.

## Source access rules

Legacy access is forbidden. Canonical and governance documents are the only
design sources for this task.

## Assumptions

- `ApplicationConfig` is introduced as a canonical DP1 application-runtime
  configuration model.
- Only `ApplicationConfig.schema_version` and `ApplicationConfig.logging` are
  defined in the current task.
