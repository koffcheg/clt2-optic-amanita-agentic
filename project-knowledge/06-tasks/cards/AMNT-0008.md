## Summary

Ця task card визначає виконання наступного knowledge-only кроку після `AMNT-0007`: винести `IMeasurementStage` draft у canonical DP1 stage interface card.

Ця задача не передбачає змін production code, build/deployment, tests або runtime-contract implementation.

## Goal

Підготувати контрольований план і межі для створення **однієї** canonical domain card:

- canonical card для `IMeasurementStage`;
- перенесення та нормалізація вже зафіксованого draft-контенту;
- збереження узгодженості з наявними DP1 type/RPC/network cards;
- без створення інших stage cards у межах цієї task card.

## In scope

- інвентаризація `IMeasurementStage` draft з `AMNT-0007`;
- визначення цільового canonical file path та card id для DP1 stage interface card;
- підготовка mapping: `draft section -> canonical card sections`;
- фіксація open questions та preconditions перед створенням canonical card;
- мінімальний план валідації knowledge-only змін.

## Out of scope

- створення canonical domain card у цій ітерації;
- створення інших stage interface cards (`IPrepStage`, `IRadiometricStage`, тощо);
- зміни production code (`datapro1/src/*`, `datapro2/src/*`);
- зміни CMake/build, Docker/deployment, tests, `.vscode`, local settings;
- зміни runtime payload або DP1 -> DP2 protocol semantics.

## Inputs and source of truth

- `project-knowledge/06-tasks/cards/AMNT-0007.md` (джерело draft `IMeasurementStage`);
- `project-knowledge/02-dp1/DP1_INDEX.md`;
- `project-knowledge/02-dp1/DP1_CARDS_INDEX.md`;
- релевантні чинні DP1 cards про `TOptionsMeasurement`, `TDrawMeasurement`, `TDataRes`, `serialize_dp1_res`, `dp1_tr_res2dp2_connection`.

## Constraints

- працювати строго в межах цієї task card;
- не створювати нові task cards;
- не створювати canonical card в цій task card;
- не змінювати `AMNT-0007.md`;
- не виконувати broad refactor knowledge base;
- усі твердження про контракти мають бути верифіковані по коду/наявних cards під час наступної ітерації.

## Planned deliverables

1. Target spec для майбутньої canonical card:
   - пропонований file path;
   - пропонований card id;
   - перелік обов'язкових секцій.

2. Transfer map з `AMNT-0007`:
   - які розділи переносяться без змін;
   - які розділи потребують переформулювання;
   - які твердження мають статус assumptions/open questions.

3. Consistency checklist:
   - узгодження з DP1 types/RPC/network cards;
   - перевірка відсутності несанкціонованих контрактних змін.

4. Iteration report у форматі `AGENTS.md`.

## Risks

- ризик змішування task-level чернетки і canonical domain knowledge;
- ризик неявної зміни контрактної семантики під час «редакторського» перенесення;
- ризик дублювання/розсинхрону між майбутньою canonical card та наявними DP1 cards.

## Validation approach

Knowledge-only validation:

- перевірка наявності всіх посилань на source files/cards;
- перевірка, що не створено нових domain cards у цій ітерації;
- перевірка, що не зачеплено code/build/deployment/tests;
- перевірка, що scope обмежено лише `IMeasurementStage`.

## Definition of done

Задача вважається виконаною, якщо:

- підготовлено target spec і transfer map для винесення `IMeasurementStage` у canonical DP1 stage interface card;
- чітко зафіксовано, що canonical card не створюється в цій ітерації;
- немає змін за межами дозволених файлів;
- надано iteration report за шаблоном `AGENTS.md`.
