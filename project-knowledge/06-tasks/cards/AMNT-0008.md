### 2) Transfer map: `AMNT-0007` draft -> майбутня canonical card

Джерело: секція draft `IMeasurementStage` у `project-knowledge/06-tasks/cards/AMNT-0007.md`.

#### 2.1 Перенести без змін (semantic-preserving transfer)

- `Definition` (роль stage як перетворення candidate/segmentation artifacts у measurement-level output).
- `Compatibility contract` частина в `Theorem / Contract`:
  - payload-stability щодо `TDataRes`/`serialize_dp1_res`;
  - незмінна зовнішня boundary-семантика `send_res_to_dp2`.
- `Connections` до існуючих DP1 cards (`TOptionsMeasurement`, `TDrawMeasurement`, `TDataRes`, RPC/net boundary).

#### 2.2 Переформулювати (editorial normalization, без зміни контракту)

- `Input contract (logical)` — уточнити неймінг candidate artifacts без фіксації implementation-specific DTO.
- `Output contract (logical)` — відокремити measurement payload від optional draw geometry більш формально.
- `Determinism / QoS contract` — винести hard requirements (determinism, no blocking I/O, controlled allocations) у компактний normative список.
- `Failure cases` — нормалізувати у форматі `condition -> expected behavior`.
- `Typical misuse` — прибрати task-level wording, залишити лише canonical anti-patterns.

#### 2.3 Залишити як `Assumptions` / `Open questions`

- Canonical input DTO shape (`contour-first` / `CC-first` / `hybrid`) до окремого погодження.
- Точна межа відповідальності між `IObjectFilterStage` та `IMeasurementStage`.
- Необхідність explicit `confidence/quality` поля при потенційних змінах layout.
- Політика partial/empty output під SLA pressure (до formal QoS policy).
