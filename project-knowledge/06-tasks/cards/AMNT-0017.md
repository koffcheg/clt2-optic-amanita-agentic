## Summary

Синхронізувати наявні canonical-знання МКМФ із затвердженим планом доробки бази
знань CameraProSim/DP1 у межах, що стосуються тільки МКМФ: Stage 0, бінування,
транспортна пам'ять і наслідки для валідації.

## Goal

Наявна `специфікація МКМФ`, memory ownership policy і validation card МКМФ
мають явно розрізняти канонічний input кадру, транспортну пам'ять і пам'ять
алгоритмічної історії.

## In scope

- Уточнити, що МКМФ отримує фактичний канонічний input після Stage 0 / input
  normalization.
- Уточнити, як DP1/software binning і camera-side binning впливають на history
  МКМФ.
- Уточнити умови reset для history МКМФ при зміні frame layout semantics.
- Уточнити, що transport IPC slots не є сховищем історії МКМФ.
- Додати validation checks для нових правил володіння і reset.

## Out of scope

- Створення карток Stage 0.
- Створення карток CameraProSim або IPC protocol.
- Створення tests, fixtures, mocks, snapshots або golden files.
- Зміни коду.
- Читання або використання legacy knowledge як джерела.

## User constraints

- Почати роботу за затвердженим планом.
- Тримати scope тільки в межах того, що стосується МКМФ.

## Source access rules

Тільки canonical development. Legacy access заборонений.

## Assumptions

- Картки Stage 0 / CameraProSim не canonicalized у межах цього task.
- Наявний `CyclicFrameBuffer` залишається canonical runtime-history structure
  для МКМФ; нова картка `TemporalHistoryBuffer` не вводиться.
