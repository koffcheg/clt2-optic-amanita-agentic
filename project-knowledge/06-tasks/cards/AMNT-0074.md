## Summary

Extend the typed `datapro1_v2` prep tile configuration with execution and
aggregation settings required by the future oneTBB-only tile route.

## Goal

Add typed config structures, strict parser support, validation, and unit-test
coverage for `prep.parameters.tiles.execution` and
`prep.parameters.tiles.aggregation` without changing runtime tile behavior.

## In scope

- Add tile execution and aggregation enums and structs.
- Extend `PrepTilesParametersConfig`.
- Parse optional `execution` and `aggregation` objects with default values.
- Reject unknown keys in `tiles`, `tiles.execution`, and `tiles.aggregation`.
- Validate non-negative thread settings and supported enum strings.
- Update existing config unit tests with explicit user approval.

## Out of scope

- Implementing `TilePipeline`.
- Implementing `OneTbbTileExecutor`.
- Connecting tile route to runtime.
- Adding serial fallback, backend dispatch, OpenMP, or a custom thread pool.
- Adding a `backend` field under `tiles.execution`.
- Adding logging or profiling fields under `prep.parameters.tiles`.
- Changing `application_config_datapro1_v2.json`.
- Changing full-frame behavior.
- Updating Project Knowledge outside this task card and task index entry.

## User constraints

- Do not change Project Knowledge base without explicit approval.
- Do not use legacy code without explicit task-card approval.
- Do not add new logging levels.
- Do not add new profiling levels.
- Do not add logging/profiling switches in `prep.parameters.tiles`.
- Do not add a serial backend or `backend` field.
- User explicitly approved creating this task card and updating/creating tests.

## Source access rules

Canonical development route only. Legacy sources are forbidden and must not be
used as implementation sources.

## Assumptions

- This task changes the typed config contract only; runtime behavior is not
changed in this task.
- Existing `ParameterMap` parser helpers are sufficient for nested tile config
objects.
- Unit coverage should extend the existing config test file rather than adding
new test infrastructure.
