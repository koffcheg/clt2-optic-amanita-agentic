## Summary

Align `datapro1_v2` stage execution method names with the canonical stage
contract by using C++ overloads named `process(...)` instead of route-specific
method names.

## Goal

Stage interfaces and implemented radiometric stage use `process(...)` overloads.
Canonical knowledge clarifies that route-specific C++ execution methods must be
named `process(...)`, while exact parameter lists remain open.

## In scope

- Rename stage interface execution methods in `datapro1_v2` headers.
- Rename the implemented radiometric stage methods and runtime call site.
- Update `dp1.pipeline.stage_contract` with the partial naming clarification.
- Update `dp1.pipeline.stage_domain_bindings` only to clarify semantic form.
- Update this task card and task index.

## Out of scope

- Introducing `TileStageContext`.
- Fixing exact C++ signatures for all routes.
- Editing `dp1.validation.canonical_conformance`.
- Renaming configuration keys such as `radiometric`.
- Changing algorithmic behavior or data contracts.
- Adding new tests, fixtures, or test infrastructure.

## User constraints

- Do not use a wrapper context for tile route.
- Do not define exact route signatures in Project Knowledge yet.
- Do not edit `dp1.validation.canonical_conformance.md`.
- Keep the work minimal and scoped to naming/knowledge clarification.
