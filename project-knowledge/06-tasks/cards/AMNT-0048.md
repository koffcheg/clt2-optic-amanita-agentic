## Summary

Підготувати canonical Project Knowledge для `Stage0 Input Normalization` і
`CanonicalFrame` baseline. Задача є документаційною: код, тести, runtime
CameraProSim, IPC layout і binning-алгоритм не змінюються.

## Goal

Після задачі AI-кодер має отримати формальний route для майбутньої реалізації
`Stage0.1`: `FramePacket -> Stage0 -> CanonicalFrame -> Stage1 Prep`.

## In scope

- Створити картку `Stage0 Input Normalization`.
- Створити картку структури `CanonicalFrame`.
- Оновити Stage I/O matrix і domain bindings.
- Оновити configuration registry і `PipelineConfig C` для Stage0.1.
- Звузити відповідальність `Prep` до processing geometry.
- Оновити memory ownership і coordinate policy для `CanonicalFrame`.
- Оновити англомовні індекси навігації.

## Out of scope

- Будь-які зміни C++ коду.
- Binning implementation або Stage0.2.
- ROI, tiles, Stage1.1 implementation.
- CameraProSim runtime або IPC shared-memory layout.
- DP2, OverlayRunner, validation fixtures або automated tests.

## User constraints

- Карточки писати українською мовою.
- Документи типу `_INDEX` і `_POLICY` писати англійською мовою.
- Не змішувати binning у Stage0.1.
- Не робити реалізацію коду.

## Source access rules

Canonical development. Legacy access is forbidden.

## Assumptions

- `input_route` у Stage0.1 є validation contract для pass-through
  `CanonicalFrame`.
- `CanonicalFrame` може містити future provenance fields для binning, але
  Stage0.1 встановлює no-op semantics.
- Binning потребує окремої StageSpec перед code generation.
