## Summary

Simplify the default DP1 v2 application authoring JSON so it exposes only the
logging/profiling settings used by the minimal runtime slice, while preserving
the full typed C++ configuration model and accepting omitted advanced fields.

## Goal

`application_config_datapro1_v2.json` parses with a reduced logging/profiling
surface, advanced fields may be omitted, and explicit invalid advanced values
are still rejected.

## In scope

- Reduce only the default DP1 v2 application JSON logging/profiling sections.
- Make advanced logging/profiling parser fields optional with typed defaults.
- Preserve strict unknown-key rejection.
- Update existing config parser unit tests for minimal and full config forms.

## Out of scope

- Removing fields from C++ typed config structs.
- Changing canonical configuration cards.
- Adding new config fields.
- Implementing MDC, async appenders, raw trace, operation timing, external
  trace, JSON/CSV report writing, or profiling log events.
- Changing DP1 pipeline behavior.

## User constraints

- Use log4cxx for future logging, not `std::cout`, `std::cerr`, or `printf`.
- Logging must be structured key-value messages and must not become data path.
- Profiling records remain runtime structures; logging may only emit bounded
  summaries.
- Do not log image/payload structures or per-tile/per-pixel/per-object spam.

## Source access rules

Canonical DP1 configuration and profiling/logging policy are allowed sources.
Legacy access is forbidden for this task.

## Assumptions

- Existing typed defaults in `dp1v2::LoggingConfig` and
  `dp1v2::ProfilingConfig` are the implementation defaults for omitted fields.
- Existing unit config tests may be updated because the user explicitly included
  them in the task acceptance criteria.
