## Summary

Formalize the existing `ApplicationConfig.visualization` runtime section as a
canonical DP1 application configuration card.

## Goal

Add `dp1.config.application.visualization` and link it from the root
application configuration card and canonical DP1 index.

## In scope

- Create the visualization application configuration card.
- Write the new card body in Ukrainian except template section names,
  technical identifiers, paths, code snippets, and field names.
- Provide detailed `Fields / Interface` entries following the style of
  `dp1.config.application.logging`.
- Update `dp1.config.application` so it contains the new child section.
- Update `DP1_CANONICAL_INDEX.md` and `TASKS_INDEX.md`.

## Out of scope

- C++ source changes.
- Runtime JSON changes.
- Tests, fixtures, mocks, or generated artifacts.
- Async visualization, renderer configuration, DP2, IPC, tiles, and new stage
  visualization outputs.
- Full visualization artifact manifest/schema design.

## User constraints

- The new domain/config card must be fully Ukrainian except template section
  names.
- `Fields / Interface` must be detailed like
  `dp1.config.application.logging.md`.

## Source access rules

Canonical development only. Legacy sources are forbidden for this task.

- The card must not promise modes or stages that the runtime parser rejects.
