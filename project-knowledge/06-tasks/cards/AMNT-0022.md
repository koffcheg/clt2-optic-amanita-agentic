## Summary

Ця task card готує першу обмежену DP1 codegen-ітерацію.

Перша code task обмежується файловим input adapter, який створює canonical `FramePacket` з grayscale frame source і надає достатній evidence для review.

## Goal

Дозволити перший executable DP1 codegen slice:

```text
FileFrameSource -> FramePacket -> minimal validation/evidence
```

Результат має бути малим, придатним для review і прямо прив'язаним до canonical DP1 input contracts.

## In scope

- Зафіксувати межу першої codegen-задачі.
- Використати canonical `FramePacket` як output boundary.
- Використати canonical `PipelineConfig.input_route` як input metadata/config reference.
- Вимагати мінімальний validation/evidence report.
- Залишити задачу достатньо малою, щоб оцінити дисципліну агента.

## Out of scope

- CameraProSim.
- POSIX Shared Memory.
- POSIX Message Queue.
- CameraPro runtime integration.
- TileScheduler.
- Full DP1 pipeline implementation.
- Binning / coordinate remapping implementation.
- Candidate extraction, segmentation або measurement.
- Broad class hierarchy або full DP1 framework scaffolding.
- CMake/build changes без окремого approval у наступній task.
- New tests/fixtures/directories без окремого approval від reviewer. Validation evidence все одно обов'язковий.

## User constraints

- Не генерувати повну структуру DP1 за одну ітерацію.
- Не використовувати legacy code як source of architecture, якщо окрема task явно цього не дозволяє.
- Не розширювати scope від file input до CameraProSim або IPC.
- Надавати перевагу working vertical slice, а не декоративним interfaces.
- Кожен generated patch має надати evidence.

## Source access rules

Для цієї canonical codegen task legacy access заборонений.

Агент має читати тільки listed canonical sources і validation card, якщо reviewer явно не дозволив додаткові файли.

## Assumptions

- `develop` є starting branch для цієї preparation task.
- `FramePacket` є canonical Raw/Input boundary для першого codegen slice.
- Перша codegen-ітерація навмисно менша за full DP1 route.
- Binning і coordinate mapping будуть окремою наступною ітерацією після review першого input slice.
