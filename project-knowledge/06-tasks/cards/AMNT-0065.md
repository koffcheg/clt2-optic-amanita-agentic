## Summary

Add a small runtime formatter that turns existing `SingleFramePipelineResult`
profiling and status snapshot data into one bounded structured key-value log
message.

## Goal

The formatter returns a stable `event=frame_profile` message for completed and
failed frame routes without logging directly, without reading OpenCV payloads,
and without creating new profiling records.

## In scope

- Add a formatter header and implementation under `dp1v2/runtime`.
- Include frame identity metadata in `FrameContextSnapshot` so the formatter can
  read it from the snapshot.
- Format frame duration, tile count, stage timings, lifecycle status/reason,
  diagnostics-derived controlled failure marker, and route status summaries.
- Add focused unit tests for full-frame, tiles controlled failure, and empty
  stage timings.
- Update local CMake source lists.

## Out of scope

- Runtime loop integration.
- New logging calls.
- log4cxx dependency inside the formatter.
- Aggregation, median/p95/p99, JSON/CSV profiling reports, external tracing, or
  P3 operation-level profiling.
- Configuration changes or new configuration fields.
- Reading or serializing image buffers, masks, contours, candidates,
  measurements, or payload data.

## User constraints

- Use current P1/P2/P4 profiling data already stored in runtime structures.
- Do not implement P3, full P5 aggregation, external trace, or report writers.
- Do not write profiling as a separate log event per stage.
- Structured message must be bounded and stable key-value text.
- Formatter must not call log4cxx.
- Preserve tiles controlled failure behavior: radiometric correction remains
  `NotStarted` without a radiometric `StageTiming`.

## Source access rules

Canonical DP1 logging/profiling/runtime knowledge is allowed. Legacy access is
forbidden.

## Assumptions

- The explicit request to add unit tests is approval for the focused formatter
  test file and CMake additions.
- `FrameContextSnapshot` may be extended with existing frame identity metadata
  because this is local runtime metadata and not an external exchange format.
- The known `prep.tiles.downstream_not_connected` diagnostic code is the
  controlled-failure marker for the current tiles route.

## Result

Completed. Added `format_frame_profile_log(const SingleFramePipelineResult&)`
as a pure formatter with no log4cxx or OpenCV dependency. The formatter emits
one bounded structured `event=frame_profile` key-value message from existing
snapshot data: lifecycle status/reason, frame identity, frame duration, tile
count, stage timing summary, route/status summary, and the known tiles
controlled-failure marker.

`FrameContextSnapshot` now carries existing frame identity metadata
(`frame_id`, `camera_id`, and `source_id`) so formatter output does not need to
read the mutable `FrameContext`.

Validation passed:

- `cmake --build build-dp1v2-tests --target dp1v2_unit_tests`
- `./build-dp1v2-tests/dp1v2_unit_tests --gtest_filter=ProfilingLogFormatterTest.*`
- `./build-dp1v2-tests/dp1v2_unit_tests`
- `cmake --build build-dp1v2-tests --target datapro1_v2`

Formatter dependency check found no `log4cxx`, OpenCV, `cv::`, or `Mat`
references in the formatter header/source or formatter unit test.

## Follow-up

Runtime-loop integration of the formatter is out of scope for this task.
