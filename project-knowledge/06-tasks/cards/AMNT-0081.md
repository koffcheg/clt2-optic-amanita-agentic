## Summary

Implement per-tile `inverse_median` state ownership for the `datapro1_v2` tile route.

## Goal

Each stable `{camera_id, tile_id}` in the tile route owns an independent
`InverseMedianFilter` history. Tile state is prepared before oneTBB execution and
worker threads only use already prepared state.

## In scope

- Add `TileRadiometricStateStore`.
- Add key/signature types for per-tile radiometric state compatibility.
- Update `RadiometricStage` tile `inverse_median` support.
- Invoke tile state preparation in `TilePipeline` before `TileExecutor`.
- Add or update focused unit tests for per-tile state ownership.

## Out of scope

- Task 10 runtime dispatch changes beyond already existing tile pipeline path.
- New tile execution backends or serial fallback.
- `tiles.execution.backend` config.
- Mandatory image stitching/merge.
- New logging/profiling levels or switches.
- Project Knowledge updates outside this task card.

## User constraints

- Do not use one shared full-frame `InverseMedianFilter` for all tiles.
- Do not include `frame_id` in the tile state key.
- Do not create tile state lazily in oneTBB worker path.
- Do not write `FrameContext` from worker threads.
- Do not log per-tile/per-pixel hot path.
- Preserve full-frame behavior unless required by the tile route implementation.
- Tests may be added or changed for this task.

## Source access rules

Canonical development only. Legacy sources are forbidden for code generation.

## Assumptions

- Tasks 1-8 of the tile route series are present in the feature branch.
- `TileRawView` has enough metadata for the key/signature and output metadata.
- Tile radiometric image output is frame-local unless an owning artifact contract
  is added in a future task.

## Result

Implemented per-tile `inverse_median` state ownership for the tile route:

- added `TileRadiometricStateStore` with stable `{camera_id, tile_id}` keys,
  compatibility signatures, prepared-state lookup, stale-state removal, and no
  worker-path insertion;
- updated `RadiometricStage` to expose tile capability for configured
  `inverse_median`, prepare tile states before execution, and process each tile
  through its own `InverseMedianFilter`;
- connected tile state preparation in `TilePipeline` before `TileExecutor`;
- updated CMake targets;
- added focused unit tests for separate tile histories, state persistence,
  signature reset, missing prepared state behavior, full-frame/tile state
  separation, and per-tile warm-up independence;
- updated previous skeleton tests that expected unsupported tile radiometric
  behavior.
