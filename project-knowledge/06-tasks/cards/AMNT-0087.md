## Summary

Integrate the concrete `Stage2BoundaryAdapter` into `FullFramePipeline` so the
full-frame route exposes a stable `stage2.processing_frame` boundary after
`RadiometricStage`.

## Goal

After `RadiometricStage`, full-frame downstream code must use the selected
Stage 2 processing frame rather than reading `radiometric_result.output.frame`
directly.

## In scope

- Add `Stage2BoundaryAdapter&` to `FullFramePipeline`.
- Update the full-frame runtime construction call site.
- Select Stage 2 output for `Completed`, `Disabled`, and `Skipped` radiometric
  statuses.
- Return frame failure for `Failed` and `Unsupported`.
- Record radiometric timing with the selected Stage 2 output format.
- Register `stage2.processing_frame` provenance.
- Add or update focused tests if a suitable existing test target exists.

## Out of scope

- Tile route changes.
- New boundary adapter interfaces or polymorphic adapters.
- Domain card, protocol card, or stage spec rewrites.
- Stage 3 implementation.
- Broad runtime refactoring.

## User constraints

- `RadiometricStage` must keep reporting its real status.
- Bypass is formed by concrete `Stage2BoundaryAdapter`.
- Do not create `IBoundaryAdapter`.
- `FrameContext` registers metadata/provenance only and does not store image
  payload.
- Bypass conversion buffers stay in `Stage2BoundaryWorkspace`.
- U8 bypass uses shallow `cv::Mat` assignment.
- U16 bypass performs one explicit `CV_16U -> CV_8U` conversion through
  `PixelRange`.
- New production and Doxygen comments must be in English.
- Tests may be added or updated if needed.

## Source access rules

Canonical development only. Legacy sources are forbidden for code generation.

## Assumptions

- `Stage2BoundaryAdapter` already implements the accepted Stage 2 boundary
  selection contract.
- Existing `FullFramePipeline` is the only full-frame construction call site.
- Existing build presets under `build-*` can validate the change.

- Inject `Stage2BoundaryAdapter&` into `FullFramePipeline`.
- Use `std::optional<Stage2FullFrameSelection>` in `process(...)`.
- Move radiometric timing recording after Stage 2 selection for successful
  selectable statuses.
- Use `stage2_selection->frame.pixel_format` as radiometric `output_format`.

## Risks

- Ordering change in profiling could alter existing log expectations.
- Adapter selection can throw on invalid raw bypass inputs or invalid
  `PixelRange`; this is expected contract enforcement, but it must not be used
  for `Failed` or `Unsupported` radiometric statuses.

- Run focused existing tests if a relevant target exists.

## Execution notes

Created before implementation as the active task card for this change.
Implemented full-frame runtime wiring through the concrete

## Result

`FullFramePipeline` now receives `Stage2BoundaryAdapter&`, selects
`stage2.processing_frame` after selectable radiometric statuses, registers the
Stage 2 boundary artifact, and records radiometric output profiling from the
selected boundary frame. Existing pipeline tests now cover `Disabled + U16 ->
U8` profiling.

## Follow-up

Stage 3 and later full-frame downstream stages should consume
`stage2_selection->frame` instead of `radiometric_result.output.frame`.
