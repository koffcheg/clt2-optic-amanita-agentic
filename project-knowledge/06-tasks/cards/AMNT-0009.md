## Summary

Ця task card фіксує підготовку knowledge-only ітерації для **batch-створення** canonical DP1 downstream stage interface cards для:
- `ICandidateExtractionStage`
- `ISegmentationStage`
- `IObjectFilterStage`

У цій ітерації створюється лише task-level план і межі виконання; самі domain cards не створюються.

## Goal

Підготувати контрольований scope, transfer strategy та validation рамку для наступної ітерації, у якій буде створено три canonical DP1 stage interface cards без несанкціонованих змін контрактів.

## In scope

- визначення цільового переліку canonical cards для трьох downstream stage interfaces;
- підготовка структури перенесення (draft -> canonical) для кожного stage;
- фіксація preconditions та consistency checks перед створенням domain cards;
- визначення обмежень, щоб уникнути scope drift у code/build/runtime contracts.

## Out of scope

- створення будь-яких domain cards у `project-knowledge/02-dp1/cards/` в межах цієї ітерації;
- зміни production коду (`datapro1/src/*`, `datapro2/src/*`);
- зміни build/CMake, Docker/deployment, tests, `.vscode`;
- зміна публічних контрактів, wire formats, RPC/TCP semantics;
- масова синхронізація або реструктуризація knowledge base.

## User constraints

- змінювати тільки:
  - `project-knowledge/06-tasks/cards/AMNT-0009.md`
  - `project-knowledge/06-tasks/TASKS_INDEX.md`
- у цій ітерації не створювати самі canonical domain cards;
- не змінювати code/build/Docker/tests/.vscode.

## Assumptions

- downstream stage interfaces уже мають наявний draft-контекст у попередніх task-level матеріалах або суміжних notes;
- canonical cards для `ICandidateExtractionStage`, `ISegmentationStage`, `IObjectFilterStage` будуть створюватися окремою погодженою ітерацією;
- всі contract-sensitive твердження перед фіналізацією cards мають бути верифіковані по коду та чинних protocol/type cards.
