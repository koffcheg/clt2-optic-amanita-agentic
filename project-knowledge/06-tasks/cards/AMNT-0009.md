## Summary

Оновлено план DP1_v2 так, щоб порядок виконання був строго від загального до часткового: спочатку запуск нового модуля і foundation конфігурації, потім алгоритмічна міграція/розширення.

## Goal

Зафіксувати обов'язкову prerequisite-послідовність і узгодити вже виконані out-of-order кроки (A.1/A.2) з новим порядком через park/reintegrate підхід.

## In scope

- Додати в план окрему передфазу Phase 0 (bootstrap + config foundation).
- Перебудувати checklist і phase grouping під порядок general -> specific.
- Оновити execution quickstart invariants/checklists під Phase 0-first.
- Оновити phase tracker (active phase, current iteration focus, parked artifacts).
- Додати changelog entry і оновити tasks index.
- Реалізувати базовий config-layer у `datapro1_v2` на основі мінімального піднабору legacy config.
- Прибрати test/debug startup behavior із runtime entrypoint.

## Out of scope

- Повний перенос усіх legacy config полів у DP1_v2.
- Зміни DP1->DP2 schema/message-id/serializer/transport.
- Будь-які зміни legacy DP1 runtime path.

## User constraints

- Спочатку обов'язкові попередні кроки (запуск і конфігурація), потім повернення до раніше розпочатих алгоритмічних кроків.
- Мінімальні локальні зміни у межах планувальних документів.
- Не змінювати контракти обміну DP1->DP2.

## Assumptions

- Поточні A.1/A.2 артефакти корисні, але мають бути реінтегровані тільки після завершення prerequisite-фази.
- Плановий документ є authoritative для порядку виконання DP1_v2 subtasks.

## Result

- План і tracker приведені до послідовності: запуск+конфігурація -> алгоритмічне розширення.
- Документація синхронізована між ключовими файлами.
- Реалізовано базовий config-layer (`config.hpp` + `config.cpp`) і стартовий config JSON для `datapro1_v2`.
