## Summary

Connect existing DP1 v2 frame profiling data and frame-profile formatter to the
runtime loop through bounded log4cxx emission, and add a minimal runtime
aggregation layer for window and run summaries.

## Goal

Default runtime emits lifecycle and bounded aggregated profiling summaries, while
diagnostic config may emit `DEBUG event=frame_profile` per-frame reports. The
controlled prep-tiles route emits a bounded `WARN event=frame_failed` summary
without changing pipeline behavior.

## In scope

- Add a small runtime profiling aggregator for frame counts, frame duration
  min/avg/max, executed-stage average durations, and avg/max tile count.
- Add bounded structured summary formatters for failed frames, window summaries,
  and run summaries.
- Integrate log4cxx logging in the runtime loop using `amanita.dp1.runtime` and
  `amanita.dp1.profiling`.
- Respect existing `ApplicationConfig.logging` and `ApplicationConfig.profiling`
  switches.
- Add focused unit tests for aggregation and summary formatting.

## Out of scope

- Full P5 percentile aggregation, including median, p95, or p99.
- P3 operation-level profiling.
- Budget warning calculation without an approved budget model.
- JSON/CSV profiling report writers.
- External trace integration.
- MDC helpers.
- Per-stage log event stream.
- New configuration fields.
- Project Knowledge domain-card updates.

## User constraints

- Use log4cxx for logging, not `std::cout`, `std::cerr`, `printf`, or ad-hoc
  writers.
- Logging must be structured key-value messages.
- Logging must not change pipeline behavior and must not become a data path.
- Profiling records must stay in runtime structures; logging may output only
  bounded summaries.
- Do not log `cv::Mat`, images, masks, contours, candidates, measurements, or
  payloads.
- Do not add per-tile, per-pixel, per-object, or per-stage log spam.
- Preserve the current prep-tiles controlled failure behavior and the absence of
  radiometric `StageTiming` on that route.

## Source access rules

Canonical DP1 logging, profiling, configuration, and runtime context knowledge
are allowed sources. Legacy access is forbidden.

## Assumptions

- The user request explicitly approves the focused unit tests required by the
  acceptance criteria.
- Minimal aggregation may report averages and max values only; percentile
  fields remain out of scope.
- `summary_every_n_frames=0` disables periodic window summary emission.

## Result

Completed. Added a pure runtime profiling aggregator and bounded structured
formatters for controlled frame failures, window summaries, and run summaries.
Integrated the logging bridge in the DP1 v2 runtime loop with log4cxx loggers:
`amanita.dp1.runtime` for lifecycle/failure events and
`amanita.dp1.profiling` for profiling reports and summaries.

Default config remains bounded: lifecycle logs and window/run summaries are
enabled, while detailed `DEBUG event=frame_profile` emission remains gated by
`profiling.reports.emit_frame_reports`. The existing prep-tiles controlled
failure route is preserved: `tile_count` is aggregated and reported,
`radiometric_correction` remains `NotStarted`, and no radiometric
`StageTiming` is created.

Added focused unit coverage for aggregation counts, duration summaries,
stage averages, summary formatting, frame-profile emission gating, and
controlled tiles failure summary formatting. Updated the log4cxx XML so
`amanita.dp1.profiling` accepts `DEBUG` when diagnostic config enables frame
reports.

Validation passed:

- `cmake --build build-dp1v2-tests --target dp1v2_unit_tests`
- `./build-dp1v2-tests/dp1v2_unit_tests --gtest_filter=RuntimeProfilingAggregatorTest.*`
- `./build-dp1v2-tests/dp1v2_unit_tests`
- `cmake --build build-dp1v2-tests --target datapro1_v2`
- copied `datapro1_v2-log.xml` in `build-dp1v2-tests/config/` was refreshed and
  verified to contain the profiling `DEBUG` logger threshold.

Inspection found no new `std::cout`, `std::cerr`, `printf`, or `fprintf` logging.
The only remaining `std::snprintf` occurrences are URI formatting in
`UriFileFrameSource`, not logging. Runtime logging changes do not reference
`cv::Mat`, image, mask, contour, candidate, measurement, or payload data.
