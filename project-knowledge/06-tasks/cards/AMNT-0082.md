## Summary

Connect the existing `TilePipeline` into the real `datapro1_v2` runtime path and
remove the old downstream-not-connected tile controlled failure as normal
runtime behavior.

## Goal

`prep.variant = "tiles"` runs Stage0, Prep tiles, TilePipeline, oneTBB tile
execution, per-tile radiometric processing, aggregation, FrameContext summary,
and result sink/lifecycle handling.

## In scope

- Verify and adjust `process_single_frame` tile route dispatch.
- Apply `tiles.execution.opencv_num_threads` at top-level runtime setup.
- Remove old controlled downstream-not-connected classification from normal
  runtime failure/logging behavior.
- Keep full-frame route behavior unchanged.
- Update focused unit tests for tile runtime integration and profiling/logging.

## Out of scope

- Project Knowledge domain-card updates.
- Legacy code use.
- New tile execution backends, serial fallback, OpenMP, custom thread pools, or
  `tiles.execution.backend`.
- Mandatory tile image merge/stitching.
- New logging or profiling levels.
- Per-tile/per-pixel logging.
- Mid-frame oneTBB cancellation.

## User constraints

- Do not change Project Knowledge except this approved task card/index entry.
- Tests may be created or updated.
- Do not write to `FrameContext` from oneTBB worker threads.
- Do not use one full-frame inverse median state for all tiles.
- Do not leave downstream tile controlled failure as normal runtime behavior.
- Do not change full-frame behavior without need.
- Do not add logging/profiling switches under `prep.parameters.tiles`.

## Source access rules

Canonical development only. Legacy sources are forbidden for code generation.

- Previous tile-route tasks already added TBB dependency, tile config schema,
  FullFramePipeline, TileResult, TileTask, TileProcessor, TileExecutor,
  TileFrameAggregator, TilePipeline, and per-tile radiometric state ownership.
- The class name `TileExecutor` remains the local oneTBB executor name per prior
  task constraints.

## Result

Implemented the final runtime integration cleanup for the tile route:

- added a runtime-boundary helper for applying
  `tiles.execution.opencv_num_threads` before tile execution;
- wired the helper into `run_bounded_runtime_loop`;
- removed the old tile downstream-not-connected controlled-failure
  classification from runtime failure logging and frame profiling formatting;
- kept `process_single_frame` dispatching `prep.variant = "tiles"` through the
  existing `TilePipeline`;
- expanded tile route summary reason fields with skipped/disabled tile counts
  and structured output counts;
- updated CMake source lists;
- updated unit tests for tile route summary, OpenCV thread-limit behavior,
  rejected `tiles.execution.backend`, and regular failure formatting.
