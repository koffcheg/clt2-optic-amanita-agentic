## Summary

Implement a frame-level aggregator for completed tile results in `datapro1_v2`.

## Goal

Provide `TileFrameAggregator` that counts tile statuses and structured tile
outputs, applies tile frame status policy, and leaves execution, stages,
FrameContext mutation, and image merge outside the aggregator.

## In scope

- Add `TileFrameAggregationSummary`.
- Add `TileFrameAggregator::aggregate`.
- Count tile statuses and candidate/segment/object/measurement cardinalities.
- Apply `TileFrameStatusPolicy` using existing lifecycle statuses.
- Add focused unit tests approved by the user.
- Wire new files into CMake.

## Out of scope

- oneTBB execution.
- TilePipeline integration.
- Image stitching/debug merge implementation.
- New lifecycle statuses.
- New logging or profiling controls.
- Project Knowledge domain-card changes.

## User constraints

- Do not change Project Knowledge without explicit approval beyond this task card.
- Do not use legacy code.
- Do not add new logging or profiling levels.
- Do not make image merge required.
- Do not create fake completed results for unsupported behavior.
- User explicitly approved creating tests for this task.

## Source access rules

For `canonical_development`, legacy is forbidden. No legacy implementation source
is used for code generation.

## Assumptions

- Existing `FrameTerminalStatus` has no Partial or CompletedWithWarnings state.
- `PartialIfSomeTilesFailed` therefore maps partial tile failure to Completed
  with a diagnostic reason when at least one tile completed.
- Unsupported tile results are treated as frame-level failure because they
  represent unavailable downstream behavior.
