## Summary

Umbrella task card for DP1 v2 logging/profiling client surface cleanup.
The work keeps canonical runtime profiling collection active while reducing or
renaming client-facing JSON fields that have misleading semantics.

## Goal

The default application JSON exposes only the intended client controls for
logging and profiling. Internal/declarative fields may remain in C++ typed
configuration when useful, but they must not create misleading client semantics.

## In scope

- Simplify client-facing `logging` and `profiling` JSON surface.
- Rename or remove misleading client-facing fields when explicitly scoped by
  the current subtask.
- Keep frame duration, stage timings, tile count, and aggregation collection
  independent from report-emission controls.
- Update canonical profiling configuration card in Ukrainian only when a
  profiling configuration semantic changes.
- Update existing unit tests for approved config behavior changes.

## Out of scope

- External trace backend integration.
- Budget warning enablement.
- New logging mechanisms or logging frameworks.
- Broad runtime, pipeline, or stage refactoring.
- New test infrastructure, fixtures, mocks, or datasets.

## User constraints

- Follow `LOGGING_POLICY.md` and `PROFILING_POLICY.md`.
- Do not add noisy per-frame logging by default.
- Do not add external trace backends.
- Do not enable budget warnings.
- Do not complicate the real-time path.
- Profiling collection must remain the canonical runtime mechanism.
- Canonical profiling card updates must use Ukrainian language.

## Source access rules

Legacy sources are forbidden for canonical development.

## Assumptions

- Existing report-emission controls are not collection controls.
- Existing unit tests may be updated because the user approved implementation of
  config behavior changes in this cleanup context.

## Result

Task 1 completed.

- `ProfilingConfig::enabled` was renamed to `emit_reports`.
- Client JSON now uses `profiling.emit_reports`.
- `profiling.enabled` is rejected as an unknown legacy key.
- Runtime report-emission gates use `emit_reports`.
- Runtime metric collection paths remain independent from `emit_reports`.
- Canonical profiling configuration card was updated in Ukrainian only for the
  `emit_reports` rename and semantics.
- Existing unit tests were updated for the new config surface.

Task 2 completed.

- `logging.realtime_profile` and `logging.structured_messages` remain optional
  in parser input and use C++ model defaults when omitted.
- `profiling.mode`, `profiling.levels`, and `profiling.logging_bridge` remain
  optional in parser input and use C++ model defaults when omitted.
- Explicit invalid `realtime_profile`, `structured_messages=false`,
  unsupported `profiling.mode`, unsupported/duplicate profiling levels, and
  `logging_bridge.emit_budget_warnings=true` are rejected.
- Unknown keys remain rejected.
- Existing config tests now assert the hidden-field defaults for the minimal
  client config and the rejection behavior for explicit invalid values.
