## Summary

Implement a standalone canonical `inverse_median` module for the DP1
`radiometric_correction` stage. The module must be generated from canonical
cards, the stage specification, and configuration `C`, not from existing
repository implementation code.

## Goal

Produce a small, reviewable C++ module that implements temporal per-pixel
inverse median filtering for `FixedK3` and `FixedK5`, with causal streaming
behavior, explicit warm-up invalidity, signed residual output, optional median
frame output, and explicit user-facing residual conversion modes.

## In scope

- Define standalone module API and data structures for `inverse_median`.
- Support single-channel `uint8` and `uint16` input frames.
- Support `FixedK3` and `FixedK5`.
- Support `stride >= 1` with `t % stride == 0` frame selection.
- Return invalid residual until the selected-frame ring buffer is full.
- After warm-up, emit residual for every input frame using the last computed
  median.
- Produce median frame in input pixel type when requested.
- Produce `RawSigned`, `ClipToInputRange`, `ShiftToPositive`, and
  `ScaleToInputRange` output modes as explicit conversions.
- Allocate all frame buffers during construction or `reset()`, with no hot-path
  dynamic allocation in `processFrame`.
- Keep implementation independent from existing repository code logic.

## Out of scope

- Integration into the active `datapro1_v2` runtime pipeline.
- Configuration parser changes.
- Public DP1/DP2 protocol or exchange-format changes.
- Legacy behavior matching.
- Automated test creation, fixtures, mocks, snapshots, golden files, or test
  infrastructure changes without separate approval.
- `ArbitraryK8bit`, `Centered`, `SelectedOnly`, and spatial median filtering.

## User constraints

- Generate code without using any code from the repository as implementation
  source.
- Strictly follow Project Knowledge rules and principles.
- Keep the module suitable for later integration into `datapro1_v2`.
- Do not use legacy code or legacy-reference cards.
- Do not create tests unless separately approved.

## Source access rules

This is `canonical_development`. Legacy access is forbidden. Existing
`datapro1` and `datapro1_v2` code may be inspected only for future integration
file placement or build wiring, not as a source of implementation logic.

## Assumptions

- The first streamed frame has frame counter `t = 0`.
- The module may expose a small standalone API that can later be adapted to the
  canonical `process(input, context, config) -> output` stage contract.
- The exact final DP1 stage-interface signature is still open in Project
  Knowledge, so the first implementation should avoid coupling to runtime
  pipeline internals.
- OpenCV storage types may be used, but OpenCV spatial `medianBlur` must not be
  used as the inverse median algorithm.

## Result

Added standalone `inverse_median` module:
- `datapro1_v2/include/dp1v2/stages/inverse_median.hpp`
- `datapro1_v2/src/stages/inverse_median.cpp`

The module implements:
- `FixedK3` and `FixedK5`;
- causal `t % stride == 0` selected-frame updates;
- explicit warm-up invalidity;
- hold-last-median residual output after warm-up;
- `uint8 -> int16` and `uint16 -> int32` signed residual;
- optional median-frame output;
- `RawSigned`, `ClipToInputRange`, `ShiftToPositive`, and
  `ScaleToInputRange` output modes;
- construction/reset-time buffer allocation with no intentional hot-path frame
  allocation.

Wired `src/stages/inverse_median.cpp` into `datapro1_v2/CMakeLists.txt`.

Validation performed:
- `cmake --build --preset host-debug-datapro1v2`

Result:
- build completed successfully;
- no tests were created.

Review follow-up:
- replaced value-dependent `std::sort` median-of-5 with a fixed compare-swap
  network;
- factored compare-swap into `cswap()` while preserving the corrected
  compare-swap pair sequence used by the implementation;
- renamed median kernels to `fixedK3Median()` and `fixedK5Median()` so internal
  names match the canonical `FixedK3` / `FixedK5` modes;
- wrapped long public API comments to comply with the repository style guidance;
- changed `ScaleToInputRange` to apply `alpha * residual` rather than
  min-shift normalization;
- documented public API ownership, formats, lifecycle errors, and buffer reuse
  assumptions in the header;
- repeated `cmake --build --preset host-debug-datapro1v2` successfully.
