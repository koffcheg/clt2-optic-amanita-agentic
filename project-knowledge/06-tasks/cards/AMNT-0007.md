#### Definition

`IMeasurementStage` — stage-level interface, який перетворює candidate/segmentation artifacts у measurement-level output, сумісний з `TOptionsMeasurement` / `TDrawMeasurement` / `TDataRes` та downstream DP1->DP2 transport boundary.

#### Assumptions

- `IMeasurementStage` не змінює payload schema `TDataRes` у ранніх фазах DP1_v2 міграції.
- Candidate input shape наразі не має canonical card у knowledge base; використовується узгоджувальне припущення «segmentation-derived candidates + metadata». 
- VKO V20 деталізація для exact per-field measurement semantics у наданих джерелах відсутня; це позначено як open question.

#### Theorem / Contract

1. **Input contract (logical):**
   - frame/context metadata confirmed by existing DP1 structures,
   - segmentation/candidate artifacts (mask/contours/components залежно від upstream implementation),
   - runtime options snapshot (thresholds/filters/profile).

2. **Output contract (logical):**
   - measurement-level output compatible with existing DP1 result structures and DP1 -> DP2 transport boundary,
   - optional draw geometry aligned with existing DP1 result structures,
   - packing-ready payload fragment compatible with current result packaging flow.

3. **Compatibility contract:**
   - No breaking change to `serialize_dp1_res` binary expectations на фазі parity.
   - `send_res_to_dp2` boundary залишається external integration point без зміни semantics.

4. **Determinism / QoS contract:**
   - stage має бути deterministic для фіксованих input+config,
   - stage не повинен вводити blocking network/disk I/O,
   - memory allocations у hot path мають бути мінімізовані/контрольовані згідно з DP1_v2 performance constraints.

#### Interpretation

`IMeasurementStage` є мостом між image-space candidates та protocol-stable object measurements. Він замикає stage-driven pipeline у format, який сумісний з існуючим DP2 ingest contract.

#### Failure cases

- Порожні або невалідні candidate artifacts -> порожній measurement set з валідним frame envelope.
- Неконсистентні geometry/area descriptors -> candidate reject або safe default mapping (policy має бути зафіксована в окремому implementation note).
- SLA pressure/overload -> stage повертає частковий або порожній set лише за явно визначеною upstream QoS policy (неявні дропи заборонені).

#### Typical misuse

- Змішування measurement extraction з transport-side serialization в одному компоненті.
- Залежність від GUI/debug I/O в measurement hot path.
- Неявна зміна поля/розміру `TOptionsMeasurement` без versioning policy.

#### Open questions

1. Який canonical input DTO для `IMeasurementStage`: contour-first, CC-first, чи hybrid?
2. Які exact acceptance/rejection критерії між `IObjectFilterStage` та `IMeasurementStage`?
3. Чи потрібен explicit confidence/quality field, якщо це змінює `TOptionsMeasurement` layout?
4. Де проходить межа відповідальності між `ICandidateExtractionStage` і `IMeasurementStage` для derived metrics?
