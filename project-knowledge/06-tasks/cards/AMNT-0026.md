## Summary

Integrate the existing standalone `inverse_median` engine under the canonical
`RadiometricStage : IRadiometricStage` boundary. The `inverse_median` variant
must remain an engine selected by the radiometric stage through configuration,
not a separate implementation of `IRadiometricStage`.

## Goal

Make `inverse_median` ready for canonical full-frame radiometric execution while
keeping the API route-neutral enough for future tile support.

## In scope

- Use the config-owned `InverseMedianMode` and `InverseMedianOutputMode` types.
- Keep `InverseMedianFilter` as a route-neutral algorithm engine.
- Add external frame-index context for `processFrame`.
- Add `RadiometricStage : IRadiometricStage` as the stage-level variant
  dispatcher.
- Support full-frame `radiometric.variant = "inverse_median"`.
- Return explicit `Unsupported` for `inverse_median` tile execution until
  per-tile state ownership is approved.

## Out of scope

- Full pipeline executor wiring.
- Tile-route `tile_id -> InverseMedianFilter` state map.
- New tests, fixtures, mocks, snapshots, or golden files.
- Project Knowledge domain-card changes.
- Legacy analysis or migration from legacy sources.

## User constraints

- Do not use legacy sources.
- `InverseMedianFilter` must not inherit from `IRadiometricStage`.
- `RadiometricStage` must own variant selection.
- No tests unless separately approved.

## Source access rules

Canonical development only. Legacy access is forbidden.

## Assumptions

- Current uncommitted stage-interface work is user-approved context and must not
  be reverted.
- Existing standalone `inverse_median` behavior is the algorithm baseline to
  preserve while adjusting ownership and stage boundary.
- `RadiometricStage` may initially support only the `inverse_median` variant.

## Result

Completed. `inverse_median` now uses the config-owned inverse-median enum types,
keeps `InverseMedianFilter` as a standalone algorithm engine, and supports an
external `InverseMedianProcessContext.frame_index` while preserving the old
single-argument `processFrame` compatibility overload.

Added `RadiometricStage : IRadiometricStage` as the stage-level dispatcher. It
supports full-frame `radiometric.variant = "inverse_median"`, maps valid filter
output to `ProcessingFrame`, and returns explicit `Unsupported` for the
`inverse_median` tile route until per-tile history ownership is approved.

Follow-up refactor: `RadiometricStage::processFullFrame` now delegates
configuration/state checks to `validateInverseMedianFullFrameConfig` and result
mapping/validation to `makeInverseMedianFullFrameOutcome`.

Renamed the inverse-median implementation files to
`radiometric_stage.inverse_median.hpp` and
`radiometric_stage.inverse_median.cpp`, and updated build/include references.
Existing unit and visual-unit tests compile and pass after the rename; no test
logic changes were needed.
