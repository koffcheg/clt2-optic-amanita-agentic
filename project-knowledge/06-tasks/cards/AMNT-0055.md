## Summary

Insert the already implemented full-frame/L0 `PrepStage` into the DP1 v2 runtime
pipeline between `InputNormalizationStage` and `RadiometricStage`.

## Goal

Runtime execution follows:

```text
FramePacket -> InputNormalizationStage -> PrepStage(full_frame/L0) -> RadiometricStage
```

and frame profiling includes a `prep` stage timing entry.

## In scope

- Add `PrepStage` execution after successful input normalization.
- Record Prep stage timing with stage key `prep`.
- Pass the Prep output frame to `RadiometricStage`.
- Move `InputNormalizationStage` construction to `runtime.cpp`, next to
  `PrepStage` and `RadiometricStage`.
- Update the single-frame pipeline API to accept the pre-created stages.

## Out of scope

- Configuration changes.
- New tests or test infrastructure.
- Tile, ROI, or adaptive ROI Prep routes.
- Domain Project Knowledge edits.
- Broad runtime architecture refactoring.

## User constraints

- Keep the default config unchanged.
- `runtime.cpp` should create `PrepStage` and `InputNormalizationStage`
  beforehand, like `RadiometricStage`.
- Do not change production behavior beyond inserting full-frame/L0 Prep.

## Source access rules

Canonical development only. Legacy access is forbidden.

## Assumptions

- Existing `pipeline_config.stages.prep` default is `enabled=true`,
  `variant=full_frame`, `level=L0`.
- Full-frame Prep returns a non-owning view of the input `CanonicalFrame`.
- Existing tests are sufficient for this integration slice unless follow-up
  runtime-specific coverage is approved separately.

## Result

Completed. Runtime pipeline now executes `PrepStage` after successful `InputNormalizationStage` and before `RadiometricStage`. `InputNormalizationStage`, `PrepStage`, and `RadiometricStage` are created in `runtime.cpp` before the frame loop and passed into `process_single_frame`. Prep stage timing is recorded with stage key `prep`, and radiometric correction consumes the prepared frame returned by Prep.
