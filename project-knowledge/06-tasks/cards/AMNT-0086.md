## Summary

Stabilize Stage 2 full-frame artifact registration so downstream consumers see
`stage2.processing_frame` rather than the internal radiometric artifact id.

## Goal

Completed radiometric output and disabled/skipped radiometric bypass both publish
honest ProcessingFrame metadata under the stable Stage 2 boundary artifact.

## In scope

- Place `ProcessingDomain::RawIntensity` before `RadiometricResidual`.
- Add a generic `ProcessingFrame` artifact registration helper.
- Keep `register_radiometric_processing_artifact` as a wrapper.
- Add `register_stage2_boundary_processing_artifact`.
- Wire full-frame runtime registration through the Stage 2 boundary selection.
- Add or update focused unit tests as needed.

## Out of scope

- Domain card updates outside this task card.
- Broad runtime refactoring.
- Stage 3 or later stage implementation.
- Legacy `datapro1` source reads.
- Public exchange-format changes.

## User constraints

- `RadiometricStage` must keep its real status and not implement pass-through.
- Bypass is formed by concrete `Stage2BoundaryAdapter`.
- Do not create `IBoundaryAdapter`.
- `FrameContext` must not store image payload.
- Bypass conversion buffers must remain in `Stage2BoundaryWorkspace`.
- `CV_8U` bypass uses shallow `cv::Mat` assignment.
- `CV_16U` bypass uses explicit scaling through `PixelRange`.
- New production comments and Doxygen comments must be English.
- Tests may be added or changed if needed.

## Source access rules

Canonical development. Legacy access is forbidden.

  source for this slice.

  route frame-level publication can be handled separately if needed.
