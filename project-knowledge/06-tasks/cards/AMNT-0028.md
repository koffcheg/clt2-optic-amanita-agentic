## Summary

Add the minimum CMake support needed to configure, build, and test `datapro1_v2`
without configuring the full repository and without entering `manager`.

## Goal

Developers and agents can use a direct subdirectory configure:

```bash
cmake -S datapro1_v2 -B build-dp1v2-local -DCMAKE_BUILD_TYPE=Debug
cmake --build build-dp1v2-local --target datapro1_v2 -j2
cmake --build build-dp1v2-local --target dp1v2_unit_tests dp1v2_visual_unit_tests -j2
ctest --test-dir build-dp1v2-local --output-on-failure
```

## In scope

- Make `datapro1_v2/CMakeLists.txt` self-contained when it is the CMake source root.
- Find local requirements for `datapro1_v2`: Threads, OpenCV, Boost headers,
  jansson via pkg-config, and log4cxx.
- Add local `common/model`, `common/frame`, googletest, and dp1v2 test targets
  only for standalone `datapro1_v2` configures.
- Preserve existing top-level presets and full-repository behavior.

## Out of scope

- Runtime changes to AMNT-0027.
- Manager, Boost 1.85 installation, Docker deployment, OverlayRunner,
  IPC, CameraProSim, tiles, DP2 exchange, Stage0/binning, candidate extraction,
  segmentation, or measurement.
- Broad CMake redesign.

## User constraints

- Do not add runtime features.
- Do not touch manager or require Boost 1.85.
- Preserve existing top-level presets.

## Source access rules

Validation/build-system task. Legacy DP1 knowledge is not needed.

## Assumptions

- Direct `cmake -S datapro1_v2` is the narrowest validation path because it avoids
  configuring unrelated top-level subdirectories.
- Existing dp1v2 unit and visual-unit test sources are sufficient for local test
  targets; no new test code is needed.
