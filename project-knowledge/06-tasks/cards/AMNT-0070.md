## Summary

Reviewer marked the logging/profiling cleanup as NEEDS FIXES because the
client JSON parser still accepts advanced or future-facing fields that are not
wired to current DP1 v2 runtime behavior.

This task card covers the cleanup series. The first concrete task is to narrow
`application.profiling` client JSON parsing to fields that currently affect
runtime report emission and aggregation behavior.

## Goal

Make the accepted client JSON surface match current runtime behavior, so users
cannot set fields that appear to enable raw tracing, detailed operation timing,
external tracing, logging bridge behavior, report-file output, or mode/level
switching while those features are not implemented or not wired.

## In scope

- Narrow accepted `application.profiling` client JSON keys.
- Keep current internal C++ config model fields when useful for defaults or
  future design.
- Preserve the minimal accepted client surface:
  - `profiling.emit_reports`
  - `profiling.aggregation_window_frames`
  - `profiling.reports.emit_frame_reports`
  - `profiling.reports.emit_window_summary`
  - `profiling.reports.emit_run_summary`
- Add or update parser tests for rejected advanced/future client fields.
- Verify that the default application config remains valid.

## Out of scope

- Do not expand runtime profiling behavior.
- Do not implement raw trace collection.
- Do not implement operation timing switches.
- Do not implement external profiler or trace integration.
- Do not implement a logging bridge beyond currently wired bounded summaries.
- Do not implement profiling report file output.
- Do not remove internal C++ model fields unless a later task explicitly
  approves that cleanup.
- Do not update domain Project Knowledge cards without separate approval.
- Do not edit Project Knowledge except task cards created or updated for the
  current approved work.

## User constraints

- Follow `PROFILING_POLICY.md` and `LOGGING_POLICY.md`.
- Reject misleading client JSON fields that do not affect current runtime.
- Reject `profiling.mode` entirely, including `lightweight` and `detailed`.
- Reject `profiling.levels` entirely.
- Reject `profiling.raw_trace`, `profiling.operation_timing`,
  `profiling.logging_bridge`, and `profiling.external_trace` entirely.
- Do not implement new runtime features in this cleanup.
- Treat this card as the shared context for a series of cleanup tasks.
- Do not change Project Knowledge, except for task cards required by the current
  approved task workflow.

## Assumptions

- Current runtime-wired profiling behavior is limited to report emission gates,
  aggregation window sizing, and the three report-emission booleans.
- Existing `ProfilingConfig` fields can remain as internal defaults/future
  fields even when the client parser no longer accepts those JSON keys.
- `reports.format` and `reports.output_dir` are not part of the currently
  allowed client surface because report file output is out of scope.

## Execution notes

Initial code reading found `parse_profiling_config` in
`datapro1_v2/src/config/config.cpp` currently accepts advanced/future fields
that are out of scope for the current runtime.

Task 1 implementation narrowed the parser allowlists and updated existing
config parser tests to reject the advanced/future client JSON fields.

Task 2 verified the `application.profiling.reports` client surface:
`emit_frame_reports`, `emit_window_summary`, and `emit_run_summary` are the only
accepted report keys. `reports.format` and `reports.output_dir` are rejected by
the parser before runtime.

Task 3 narrowed the `application.logging` client surface to `enabled` and
`config_file`. Advanced logging fields such as `max_field_length`,
`default_level`, `mdc`, `sampling`, `async`, `logger_overrides`, and message
limits are rejected before runtime until they are explicitly wired.

Task 4 cleaned up config tests for the narrowed client contract. Tests no
longer treat full advanced logging/profiling JSON as a supported client
configuration, and reviewer-mentioned advanced fields have explicit negative
parser coverage.
