## Summary

Define the minimal canonical DP1 domain and boundary-structure package required before stage-level code generation.

## Goal

Give agents and developers explicit canonical domains, structures, and runtime/tile support objects for frames, runtime context, pixel formats, processing payloads, masks, candidates, segments, and measurements.

## In scope

- Clarify canonical DP1 data domains under `project-knowledge/02-dp1/canonical/data_domains/`.
- Add concrete structures that live inside those domains.
- Add minimal tile-local execution support structures for future parallelism documentation.
- Register the package in `DP1_CANONICAL_INDEX.md`.
- Keep structures separate from algorithms.
- Preserve the existing canonical route: `Code = f(Cards, Stage_Spec, C)`.

## Out of scope

- No production code changes.
- No `datapro1_v2` changes.
- No CMake/build/Docker/tests/.vscode changes.
- No stage spec or stage card rewrites.
- No full parallel pipeline implementation.
- No new `data_structures/` folder.

## User constraints

- Use the existing `data_domains/` folder instead of introducing a parallel structure folder.
- Separate domains from concrete structures attached to those domains.
- Treat 8-bit / 16-bit / F32 as pixel format / route-level properties.
- Separate structures from algorithms.
- Add `FrameContext` as a runtime/context object separate from `FramePacket`.
- Add minimal tile-local execution structures: `TileDesc`, `TileContext`, `TileResult`.

## Source access rules

Canonical development only. Legacy access is forbidden for this task.

## Assumptions

- Existing `data_domains/` is the correct canonical location because it is already listed in `DP1_CANONICAL_INDEX.md` source route.
- Existing raw/processing/mask/measurement domain cards should be clarified rather than duplicated.
- Exact C++ structure layout belongs to a later implementation task.
- Tile-local execution structures are target execution-support cards, not current runtime claims.

## Planned changes

- Clarify domain cards: Raw/Input, Processing, Mask, Struct, Measurement.
- Add domain-bound structures: `FramePacket`, `ProcessingFrame`, `BinaryMask`, `Candidate`, `Segment`, `MeasurementRecord`.
- Add runtime support structures: `FrameContext`, `TileDesc`, `TileContext`, `TileResult`.
- Update DP1 canonical index with domain taxonomy, domain structures, and tile-local execution support structures.
- Update task index.

## Risks

- Over-specifying implementation details before code tasks.
- Duplicating existing raw/processing/mask/measurement domain cards.
- Mixing algorithm details into data-domain cards.
- Confusing target tile-local execution support with implemented parallelism.

- verify no code/build/test files changed;
- verify no `data_structures/` folder created;
- verify domains and structures are registered in `DP1_CANONICAL_INDEX.md`;
- verify cards avoid current-runtime claims unless marked as assumptions/open questions.
