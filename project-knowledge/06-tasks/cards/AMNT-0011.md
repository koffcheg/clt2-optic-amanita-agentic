## Summary

Prepare the implementation route for the temporal inverse median filter. The
current request is analysis and planning only; production code is out of scope
until a separate command.

The temporal inverse median filter belongs to canonical DP1 as a stateful
radiometric/background-residual variant. It computes a temporal per-pixel median
over selected frames and forms:

```text
Residual_t(x, y) = I_t(x, y) - Med_t(x, y)
```

## Technical Requirements Specification Analysis

The updated technical requirements specification is consistent with the clarifications:
- Only `FixedK3` and `FixedK5` remain in scope.
- `ArbitraryK8bit` from the old technical requirements specification is explicitly out of scope for now.
- Temporal mode is only causal; future frames are not used.
- Output behavior is always hold-last-median: residual is emitted for each input
  frame after warm-up, while the median updates only on selected frames.
- `stride` means temporal frame-selection step, not OpenCV row stride.
- `stride` is configurable and may change during camera operation.
- If the temporal inverse median filter is disabled at program start,
  cyclic-buffer memory is not allocated.
- Median frame bit depth matches the actual input frame format, including after
  binning if binning was applied upstream.
- Residual uses signed widened representation: `uint8 -> int16`,
  `uint16 -> int32`.
- Dynamic-range expansion is attributed to subtraction `I_t - Med_t`, not to the
  median itself.
- User-facing range conversion is a separate step with `RawSigned`,
  `ClipToInputRange`, `ShiftToPositive`, and `ScaleToInputRange`.
- Internal pipeline default is `RawSigned`; recommended user-facing default is
  `ClipToInputRange`.

  `Code = f(Cards, Stage_Spec, C)` rule.

  `специфікація МКМФ`, future code may hide lossy type conversions.

  hidden default for internal processing.
