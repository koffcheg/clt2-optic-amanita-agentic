## Summary

Integrate the concrete `Stage2BoundaryAdapter` into the tile runtime route so
tiles expose the same stable Stage 2 processing boundary as the full-frame
route.

## Goal

After `RadiometricStage`, tile downstream code and profiling must use the
selected Stage 2 tile processing frame instead of depending directly on the
radiometric stage output shape.

## In scope

- Add `Stage2BoundaryAdapter&` to `TilePipeline` and `TileProcessor`.
- Allocate `Stage2BoundaryWorkspace` in tile execution and pre-size per-task
  bypass buffers before parallel processing.
- Select tile Stage 2 output for `Completed`, `Disabled`, and `Skipped`
  radiometric statuses.
- Keep `Failed` and `Unsupported` as frame/tile failures without pass-through.
- Record tile output format from the selected Stage 2 boundary frame.
- Update focused unit tests.

## Out of scope

- Stage 3 implementation.
- New adapter interfaces or polymorphic boundary adapters.
- FrameContext image payload storage.
- Domain card or Project Knowledge rewrites outside this task card and the task
  index.
- Broad tile runtime refactoring.

## User constraints

- `RadiometricStage` must keep reporting its real status.
- Bypass is formed by concrete `Stage2BoundaryAdapter`.
- Do not create `IBoundaryAdapter`.
- `FrameContext` registers only metadata/provenance.
- Bypass conversion buffers stay in `Stage2BoundaryWorkspace`.
- U8 bypass uses shallow `cv::Mat` assignment.
- U16 bypass performs one explicit `CV_16U -> CV_8U` conversion through
  `PixelRange`.
- Tile bypass buffers must be pre-sized before parallel execution.
- In the parallel section, do not use shared mutable containers, `push_back`,
  `emplace_back`, `clone`, `copyTo`, or shared mutable `cv::Mat` buffers.
- New production and Doxygen comments must be in English.
- Unit tests may be added or updated.
- Do not change Project Knowledge except task cards and task-card index.

## Source access rules

Canonical development only. Legacy sources are forbidden for code generation.

## Assumptions

- `Stage2BoundaryAdapter::selectTileOutput(...)` already implements the
  accepted Stage 2 tile boundary contract.
- Existing `TileExecutor` can remain index-based and can receive a shared
  workspace when each worker writes only its own task-indexed buffer.
- Existing unit targets are sufficient for focused regression coverage.

## Result

`TilePipeline` and `TileProcessor` now receive `Stage2BoundaryAdapter&`.
`TilePipeline::process(...)` creates `Stage2BoundaryWorkspace`, pre-sizes
`tile_bypass_u8_by_task` to `tasks.size()`, and passes the workspace through the
executor into each tile processor invocation. `TileProcessor::process(...)`
selects Stage 2 output for `Completed`, `Disabled`, and `Skipped` radiometric
statuses and records output format from the selected Stage 2 tile frame.

Updated focused unit tests for the new tile runtime API and added coverage for
`Radiometric Disabled + tile U16 -> U8` profiling output.

## Follow-up

Future Stage 3 tile route should consume the selected Stage 2 tile processing
frame.
