## Result

Completed.

The Project Knowledge testing route now has:
- `TESTING_POLICY.md` as the governance entry point;
- `UNIT_TESTING_GUIDE.md` for `unit` and `visual-unit`;
- `AMANITA_COMPARATOR_E2E_VALIDATION_WORKFLOW.md` for Amanita + Comparator `system-e2e` run-based validation;
- `VALIDATION_INDEX.md` as the validation route index with target test types and target directory model.

Additional policy/guidance now covers:
- expected-result changes must be classified as bug fix, contract change, or regression;
- algorithmic validation plans must cover normal, boundary, invalid/error-input, and known regression scenarios;
- unit tests should access production code through library targets or stable interfaces, not direct `.cpp` inclusion;
- agents should identify a smaller testable unit before proposing integration, system-e2e, or run-based validation for algorithmic logic.
