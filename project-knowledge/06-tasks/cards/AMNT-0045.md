## Summary

Add explicit references from the corrected `FrameContext` registry semantics to
the existing profiling policy and DP1 profiling domain.

## Goal

Prevent future agents from inventing another profiling model while working on
`FrameContext` artifact reflection.

## In scope

- State that profiling is governed by:
  - `project-knowledge/00-governance/PROFILING_POLICY.md`;
  - `project-knowledge/02-dp1/canonical/data_domains/dp1.domain.profiling.md`;
  - `project-knowledge/02-dp1/canonical/configuration/dp1.config.application.profiling.md`.
- State that registry is not a replacement for profiling storage.
- State that profiling must not pass algorithm outputs between stages.
- State that artifact refs may reference producer stage identity and timing
  identity when profiling is implemented.

## Out of scope

- No C++ profiling implementation.
- No timers.
- No profiling config changes.
- No benchmark work.

## User constraints

- Profiling is already described; do not recreate it.
- Include the root `PROFILING_POLICY.md` as the highest profiling-specific
  governance source.

## Source access rules

Canonical development. Legacy access is forbidden.

## Assumptions

- `PROFILING_POLICY.md` is active and applies to `FrameContext`, stage timing,
  operation timing, data-volume metrics, and memory-copy accounting.

## Result

Completed.

Updated the FrameContext registry profiling references without redefining
profiling structures.

Changed:

- `dp1.domain.runtime.frame_context` now states the profiling-specific source
  order: root `PROFILING_POLICY.md`, `dp1.domain.profiling`, then
  `dp1.config.application.profiling`. It also states that
  `FrameContext.artifacts` is not a replacement for `FrameContext.profiling` or
  profiling storage, and may only reference producer/timing identity as
  provenance metadata when profiling is implemented.
- `dp1.pipeline.stage_contract` now points stage-level profiling behavior to
  the same source order and states that artifact records must not become a
  profiling storage model or an algorithm-output transport channel.
- `dp1.validation.stage_contract_checks` now references the root profiling
  policy for profiling checks and adds checks that `FrameContext.artifacts` is
  not used as a second profiling model, that timing identity references are only
  provenance metadata, and that profiling records do not pass algorithm outputs
  between stages.

Validation performed by documentation review against `AMNT-0034`, `AMNT-0035`,
`AMNT-0039`, `PROFILING_POLICY.md`, `dp1.domain.profiling`, and
`dp1.config.application.profiling`.

No code, tests, profiling implementation, timers, profiling configuration
changes, Stage 0, TileScheduler, CameraProSim, missing stages, or `AMNT-0046`
work were performed.
