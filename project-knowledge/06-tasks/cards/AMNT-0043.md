## Summary

Register the existing radiometric stage output in `FrameContext` when the
current runtime executes `RadiometricStage` successfully.

## Goal

Fix the current semantic gap where a `RadiometricFullFrameOutput` can be
returned but the frame context has no artifact/provenance record for it.

## In scope

- Update current `process_single_frame(...)` flow.
- After successful `radiometric_stage.process(...)`, register:
  - id: `radiometric.processing_frame` or the id defined by `AMNT-0037`;
  - kind: processing frame;
  - domain: processing;
  - ownership: owned by stage output;
  - producer: `radiometric`;
  - parent: `raw_frame`;
  - format and geometry from the output where available.

## Out of scope

- No enhancement or later stage execution.
- No result builder changes.
- No profiling timer implementation.
- No algorithm changes.
- No tests unless separately approved.

## User constraints

- Keep the change limited to current runtime behavior.

## Source access rules

Canonical development. Legacy access is forbidden.

## Assumptions

- Current runtime only needs radiometric output reflection for this task.
- Failed or unsupported radiometric execution must not register a completed
  output artifact.

## Dependencies

Must be executed after:

- `AMNT-0034`

- `AMNT-0041`

## Planned changes

- Call radiometric artifact registration helper after successful radiometric
  output.
- Do not call it on failed or unsupported status.

## Files expected to be touched

- `datapro1_v2/src/runtime/pipeline.cpp`

## Risks

- Registering an artifact whose owning `StageOutcome` goes out of scope. The
  first registry implementation must be metadata-only, not a stored pointer to
  the output buffer.

## Validation approach

- Local build.
- Code review to ensure no output pointer is stored in `FrameContext`.

## Knowledge-base impact

none

## Execution notes

This task intentionally does not make the radiometric output feed another stage.

## Result

Completed.

Updated `datapro1_v2/src/runtime/pipeline.cpp` so the current runtime registers the radiometric processing output in `FrameContext.artifacts` after `radiometric_stage.process(...)` returns `StageExecutionStatus::Completed`. The registration uses the AMNT-0041 helper `register_radiometric_processing_artifact(frame_context, radiometric_result.output.frame)`, preserving the centralized artifact id and metadata semantics for `radiometric.processing_frame`.

The failed and unsupported radiometric paths remain unchanged and return without registering a successful radiometric output artifact. Non-completed statuses do not create a fake successful output artifact. No enhancement or later stages, result builder changes, profiling timers, algorithms, Stage 0, TileScheduler, CameraProSim, missing stages, or tests were changed.

Validation performed:

- Confirmed dependencies `AMNT-0034`, `AMNT-0040`, `AMNT-0041`, and `AMNT-0042` are completed before code changes.
- Reviewed the registration placement in `process_single_frame(...)` and confirmed it is gated by `StageExecutionStatus::Completed`.
- Built `datapro1_v2` with `cmake --build build-host-debug-full --target datapro1_v2`; build completed successfully. Existing warnings about `SingleFramePipelineResult::evidence_path` initializers remain unrelated to this task.
