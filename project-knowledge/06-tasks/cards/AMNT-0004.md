## Summary

Додати в DP1 програмне sum-binning як окремий preprocessing етап перед тайлінгом, керований через конфіг, без регресії чинного пайплайна.

## Goal

Отримати керовану фічу бінування з режимом увімк./вимк., щоб можна було запускати DP1 в різних алгоритмічних конфігураціях без зміни коду.

## In scope

- Секція `binning` у конфігу DP1.
- Читання/валідація параметрів бінування у `prg_config`.
- Застосування sum-binning до кадра перед етапом тайлінгу.
- Масштабування вимірювань назад у координати початкового кадра перед збереженням/передачею.
- Винесення нових літералів/чисел у named constants або конфіг.
- Фіксація правил feature toggle і anti-magic numbers у knowledge base (за погодженням користувача).

## Out of scope

- Hardware binning на сенсорі.
- Додавання нових типів бінування (average/max/pooling) у межах цього кроку.
- Зміни мережевого протоколу DP1->DP2 без підтвердженої необхідності.
- Широкі рефакторинги поза локальними місцями інтеграції.

## User constraints

- Стара поведінка має лишитись доступною (feature toggle).
- Кожна нова фіча має керуватись конфігом.
- У коді уникати магічних чисел і рядків.
- Зафіксувати правила в knowledge base.

## Assumptions

- На першому етапі потрібен лише sum-binning.
- Допустимі `binning_factor` значення: 1, 2, 4 (1 = вимкнено).
- Для координат застосовується зворотне масштабування без додаткових офсетів (`xoff=yoff=0`).

## Risks

- Некоректне масштабування координат у вихідних вимірах.
- Невідповідність розмірів кадра при factor > 1.
- Непередбачений вплив на продуктивність або чутливість сегментації.
- Потенційна розбіжність між кодом і knowledge base після зміни конфіг-схеми.

## Validation approach

- Локальний build DP1.
- Manual comparison сценарій: `binning.switched=false` vs `true` на тих самих вхідних кадрах.
- Перевірка коректності координат у `.json/.blob` артефактах.
- За потреби: окремий test plan без автотестів (відповідно до TESTING_POLICY).
