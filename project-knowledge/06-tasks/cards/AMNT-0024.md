## Summary

Add GoogleTest unit coverage for the canonical `dp1_v2` configuration parsing
and validation behavior introduced by AMNT-0023.

## Goal

`dp1v2_unit_tests` should cover the required cases from
`validation.dp1.config.canonical.md`, including valid canonical two-file loading,
legacy/wrapper rejection, application config validation, pipeline route
validation, stage key/variant/level validation, generic stage parameters, and
resolved `inverse_median` parameter validation.

## In scope

- New unit tests in `tests/unit/dp1/t_dp1v2_config.cpp`.
- Minimal test helper functions that write per-test temporary JSON files.
- Minimal CMake integration needed for `dp1v2_unit_tests` to compile and link
  config parser code and Jansson.
- Running the focused unit-test target after implementation.

## Out of scope

- DP1 algorithm changes.
- Runtime pipeline architecture changes.
- Public configuration contract changes beyond fixing defects exposed by tests.
- New external dependencies or test frameworks.
- New fixtures, mocks, stubs, snapshots, golden files, or large datasets.
- Amanita + Comparator validation.
- Testing `PrepRouteConfig` and `RuntimeLimitsConfig`, which AMNT-0023 deferred.

## User constraints

- First create the task and plan.
- Implement tests only after explicit confirmation.
- Tests must follow `validation.dp1.config.canonical.md`.

## Source access rules

Validation task over canonical DP1 configuration. Legacy access is forbidden.

## Assumptions

- The AMNT-0023 code changes in the current working tree are the implementation
  under test.
- Test data can be generated as small temporary JSON files inside the test
  process, without repository fixtures.
- If the config parser is not linkable from `dp1v2_unit_tests` without direct
  `.cpp` source inclusion, the first choice is minimal CMake linkage; any
  broader production extraction must be reported before proceeding.

  stopping for scope confirmation.
- Some validation-card cases may reveal AMNT-0023 implementation defects. Those
  should be fixed only when the intended canonical behavior is clear from the
  approved sources.
- `config.cpp` depends on Jansson and project include paths; the unit target may
  need precise CMake linkage to avoid accidental broad build changes.
