## Summary

Create the next bounded DP1 v2 executable slice by reusing the existing canonical
configuration, source, domain carrier, and `RadiometricStage` inverse-median code.

## Goal

Run `ApplicationConfig.source.mode = file` through URI/file source input,
construct a canonical `FramePacket` using `PipelineConfig.input_route`, execute
full-frame `RadiometricStage` with `radiometric.variant = inverse_median`, and
write reviewable evidence artifacts.

## In scope

- Reuse canonical `ApplicationConfig` and `PipelineConfig` loaders.
- Reuse or minimally extend file/URI source utilities.
- Preserve the raw `FramePacket` to `ProcessingFrame` stage boundary.
- Add minimal glue needed to execute full-frame radiometric inverse median.
- Add local evidence output for review.

- Stage0/binning beyond no-op plumbing.

## Result

Implemented minimal executable glue for the file/URI full-frame route:

- `PipelineConfig.input_route` is applied when constructing canonical `FramePacket`.
- `run_bounded_runtime_loop` owns a `RadiometricStage` instance for the run.
- Enabled `radiometric.variant = inverse_median` is executed through full-frame `RadiometricStage`.
- The route writes per-frame JSON evidence and a PNG review image when inverse median produces a completed residual.
- URI/file source paths now expand `${ENV_NAME}` placeholders before opening the source.

The route did not require touching tiles, IPC, CameraProSim, CameraPro, DP2 transport, or deleting/rebuilding `dp1_v2`.
