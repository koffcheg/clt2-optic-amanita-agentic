## Summary

Align the memory ownership policy with the new `FrameContext` artifact registry
semantics.

## Goal

Ensure future agents understand that registry records do not imply mandatory
copies or ownership transfer into `FrameContext`.

## In scope

- Add policy for artifact references stored in `FrameContext`.
- Clarify that artifact registry records may reference data owned by:
  - `FramePacket`;
  - stage output objects;
  - future external transport;
  - future tile-local contexts.
- Clarify that registry records must not extend borrowed memory lifetime.
- Add ownership vocabulary needed by the code task:
  - `OwnedByFramePacket`;
  - `OwnedByStageOutput`;
  - `BorrowedReadOnly`;
  - `ExternalTransport`;
  - `ExpiredReference` or equivalent.

## Out of scope

- No implementation of external transport.
- No CameraProSim.
- No TileScheduler.
- No ownership transfer implementation.
- No code changes.

## User constraints

- Do not broaden to CameraProSim or TileScheduler.
- Only align current policy for the existing FrameContext correction.

## Source access rules

Canonical development. Legacy access is forbidden.

## Assumptions

- Current `dp1_v2` raw input carrier is `FramePacket`.
- Current radiometric output is returned in `StageOutcome<RadiometricFullFrameOutput>`.

## Result

Completed.

Updated `dp1.domain.memory_ownership` with a Ukrainian canonical subsection for
`FrameContext.artifacts` ownership. The policy now states that artifact registry
records are bounded metadata/provenance records, not mandatory deep copies,
ownership transfers, or lifetime extensions for heavy payloads.

Added the ownership vocabulary required by this task:

- `OwnedByFramePacket`;
- `OwnedByStageOutput`;
- `BorrowedReadOnly`;
- `ExternalTransport`;
- `MetadataOnly`;
- `ExpiredReference`.

Clarified that artifact payloads may remain owned by `FramePacket`, explicit
stage output objects, future external transport boundaries, or future
tile-local contexts only when those boundaries are separately defined. Added
failure cases for implicit heavy-buffer ownership, borrowed lifetime extension,
and mutable shared-buffer misuse through the registry.

Validation performed by documentation review against `AMNT-0034`, `AMNT-0035`,
`dp1.domain.runtime.frame_context`, and the AMNT-0038 scope. No code, tests,
Stage 0, TileScheduler, CameraProSim, missing stages, AMNT-0039, or
`TASKS_INDEX.md` changes were made.
