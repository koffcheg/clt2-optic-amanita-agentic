## Summary

Prepare the minimal log4cxx XML configuration required by the current
`application_config_datapro1_v2.json` logging path.

## Goal

`logging.enabled=true` can resolve and load `config/datapro1_v2-log.xml` from
the DP1 v2 build config directory without adding runtime log spam.

## In scope

- Add `datapro1_v2/config/datapro1_v2-log.xml`.
- Define root/default logging and the requested DP1 logger names.
- Copy the XML into the build config directory with the existing DP1 v2 CMake
  config copy step.

## Out of scope

- Runtime frame profile logs.
- Window/run profiling summaries.
- Stage-level algorithmic logging.
- MDC helpers.
- Logging schema changes.
- Programmatic appenders or async appender setup from C++.
- New logging/profiling config fields.

## User constraints

- Use log4cxx, not `std::cout`, `std::cerr`, `printf`, or another logging
  framework.
- Do not log image, mask, contour, candidate, measurement, or payload data.
- Do not add per-stage, per-frame, per-tile, per-pixel, or per-object log spam.
- Profiling records remain runtime structures; logging may only output bounded
  summaries in future tasks.

## Source access rules

Canonical DP1 logging/profiling policy and configuration knowledge are allowed.
Legacy access is forbidden.

## Assumptions

- The current `ApplicationConfig.logging.config_file` path
  `config/datapro1_v2-log.xml` is the intended runtime path.
- A console appender is sufficient for the minimal working configuration.
- No unit-test target linkage changes are required because this task does not
  add log4cxx usage to unit-linked source files.
