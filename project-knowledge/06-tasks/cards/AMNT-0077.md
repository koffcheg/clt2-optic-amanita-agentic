## Summary

Implement the sequential tile processing unit for `datapro1_v2` Task 5.

## Goal

Add `TileTask` and `TileProcessor::process` so a single tile can be processed
without oneTBB and without writing to shared `FrameContext`.

## In scope

- Add `TileTask`.
- Add `TileProcessor`.
- Refactor downstream tile-worker stage interfaces to remove mutable
  `FrameContext&` from tile overloads.
- Update `RadiometricStage` tile overload and call sites.
- Add the new implementation file to the build targets.

## Out of scope

- oneTBB executor.
- Tile frame aggregation.
- Image stitching or debug merge.
- Full tile-route dispatch from `Pipeline`.
- Per-tile inverse median state implementation.
- New logging/profiling levels or tile-specific switches.
- New automated tests unless separately approved.

## User constraints

- Do not change domain Project Knowledge without approval.
- Do not use legacy code.
- Do not add serial fallback or oneTBB in this task.
- Do not pass, store, construct, or protect `FrameContext&` in `TileProcessor`.
- Do not write to `FrameContext` from tile-worker path.
- Do not log per-tile hot path.
- Do not create fake completed results for unsupported stages.

## Source access rules

Canonical development only. Legacy access is forbidden.

## Assumptions

- Current concrete downstream tile implementation exists only for
  `RadiometricStage`.
- Other downstream stage headers can be corrected at declaration level in this
  task because they are current/future worker interfaces.
- `RadiometricStage` tile route may remain `Unsupported` for `inverse_median`
  until per-tile state ownership is implemented by a later task.
