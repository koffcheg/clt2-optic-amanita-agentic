## Summary

Add a minimal frame-level duration field to the existing DP1 v2
`FrameContext.profiling` runtime data.

## Goal

Each `process_single_frame()` route that creates a `FrameContext` records total
frame processing duration without changing stage timing semantics or controlled
failure behavior.

## In scope

- Add `frame_duration_ns` to `FrameProfiling`.
- Use `std::chrono::steady_clock` for frame duration measurement.
- Record frame duration on all `process_single_frame()` return paths after
  `FrameContext` creation.
- Update existing DP1 v2 unit tests for full-frame and tiles routes.

## Out of scope

- Logging implementation.
- Aggregation, median/p95/p99, JSON/CSV reports, external trace, or raw trace.
- Operation-level profiling.
- New configuration fields or config schema changes.
- Fake stage timings for stages that did not execute.

## User constraints

- Preserve existing P2 `StageTiming` behavior.
- Preserve P4 `tile_count`.
- Preserve `prep.variant=tiles` controlled failure: radiometric correction has
  `NotStarted` status and no `StageTiming`.
- Do not log images, matrices, masks, contours, candidates, measurements, or
  payloads.
- Logging, if added in future tasks, must use log4cxx structured key-value
  messages; this task adds no logging.

## Source access rules

Canonical DP1 profiling/runtime knowledge is allowed. Legacy access is
forbidden.

## Assumptions

- A scalar `frame_duration_ns` is the approved minimal P1 subset for the current
  C++ slice.
- Packet creation failure does not create `FrameContext` and therefore does not
  create a profiling record.

## Result

Completed. `FrameProfiling` now carries `frame_duration_ns`, and
`process_single_frame()` records it through the local result helper on every
return path after `FrameContext` creation. Packet creation failure remains a
no-context result. Existing stage timing semantics are unchanged, and the tiles
controlled failure route still records `radiometric_correction` as `NotStarted`
without creating a radiometric `StageTiming`.
