## Summary

Update the existing canonical `FrameContext` card so it no longer describes
`FrameContext` as metadata-only. The corrected model is `FrameContext` as
runtime context plus artifact registry / provenance layer.

## Goal

Make the canonical `FrameContext` card compatible with Big TZ semantics without
requiring `FrameContext` to own all heavy buffers.

## In scope

- Update the definition of `FrameContext`.
- Add `FrameArtifactRegistry` as a required semantic part of `FrameContext`.
- Add knowledge-level definitions for:
  - `FrameArtifactRef`;
  - `ArtifactKind`;
  - `ArtifactDomain`;
  - `ArtifactOwnership`;
  - `ArtifactLifetime`;
  - `producer_stage`;
  - `semantic_name`;
  - `parent_artifact_id`.
- State that registry records may be metadata-only in the first implementation.
- State that registry records must not extend borrowed memory lifetimes.
- Link profiling semantics to `PROFILING_POLICY.md` and
  `dp1.domain.profiling.md`.

## Out of scope

- No code changes.
- No Stage 0 additions.
- No TileScheduler additions.
- No CameraProSim cards.
- No implementation of profiling.
- No changes to stage list or stage registry.

## User constraints

- Keep the work limited to what exists now.
- Do not implement missing pipeline stages.
- Do not introduce new architecture beyond the registry correction.

## Source access rules

Canonical development. Legacy access is forbidden.

Materials may be used only as evidence of the semantic gap, not as direct code
generation sources.

## Assumptions

- `FrameContext` can satisfy the Big TZ "data reflected in context" requirement
  by registering authoritative artifacts without owning heavy buffers.
- Existing `StageOutcome<T>` output style remains valid.

## Result

Completed.

Updated `dp1.domain.runtime.frame_context` so `FrameContext` is no longer
described as metadata-only. The canonical semantics now define `FrameContext` as
runtime context plus bounded artifact registry / provenance layer.

The updated card records the required reconciliation rules:

- explicit stage outputs remain required;
- context reflection is mandatory for authoritative frame artifacts;
- heavy-buffer ownership by `FrameContext` is not required by default.

Added knowledge-level definitions for `FrameArtifactRegistry`,
`FrameArtifactRef`, `ArtifactKind`, `ArtifactDomain`, `ArtifactOwnership`,
`ArtifactLifetime`, `producer_stage`, `semantic_name`, and
`parent_artifact_id`. The card also states that first implementation registry
records may be metadata-only, that registry records must not extend borrowed
memory lifetimes, and that profiling semantics are governed by
`PROFILING_POLICY.md` and `dp1.domain.profiling.md`.

Validation performed by documentation review against AMNT-0035 scope, AMNT-0034
decision context, `dp1.domain.memory_ownership`, `PROFILING_POLICY.md`,
`dp1.domain.profiling`, and the relevant Big TZ `FrameContext` passages. No
code or tests were changed.
