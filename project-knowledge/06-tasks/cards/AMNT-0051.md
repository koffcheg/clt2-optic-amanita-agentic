## Summary

Довести Stage0.1 CanonicalFrame baseline до стану READY після review: прибрати
runtime/config назву `acquisition`, зробити canonical key `input_normalization`,
вирівняти signature Stage0, provenance chain, unit tests і Project Knowledge.

## Goal

Поточний Stage0.1 має бути явною input normalization boundary:

```text
FramePacket -> input_normalization -> CanonicalFrame -> radiometric_correction
```

## In scope

- Перейменувати C++ Stage0 surface на `InputNormalizationStage`.
- Змінити config/runtime stage key з `acquisition` на `input_normalization`.
- Видалити підтримку старого key `acquisition` без compatibility alias.
- Змінити signature Stage0 на `process(input, context, config)`.
- Перенести `input_route` у Stage0 config wrapper.
- Змінити parent artifact для `radiometric.processing_frame` на `canonical_frame`.
- Додати Stage0.1 unit tests для U8/U16 success і mismatch failure cases.
- Синхронізувати Project Knowledge, включно з card filenames та IDs.

## Out of scope

- Runtime binning implementation.
- Sum/average binning arithmetic.
- Widened carrier policy implementation.
- Hidden conversion, clipping або scaling.
- Legacy runtime migration beyond current `datapro1_v2` slice.
- SWIR/mono16 run-based validation без окремого запуску.

## User constraints

- Старий config key `acquisition` видалити одразу.
- Якщо stage перейменовується на `input_normalization`, базу знань синхронізувати.
- Card filenames та IDs теж перейменувати.
- Зміни карточок писати українською.
- Зміни `_POLICY` та `_INDEX` документів писати англійською.

## Source access rules

Canonical development. Legacy access forbidden. Existing `datapro1_v2` code may
be used as runtime evidence and implementation target, not as legacy design
source.

## Assumptions

- Stage0.1 залишається pass-through only.
- `PipelineConfig.input_route` залишається validation contract для source frame.
- `canonical_frame` є authoritative parent для radiometric processing output.
- Existing GoogleTest/CTest wiring is the target validation route.
