## Summary

Add minimal helper functions for registering artifacts in the existing
`FrameContext` runtime helpers.

## Goal

Avoid ad hoc registry writes in `pipeline.cpp` and make artifact ids and
semantics stable for the current raw + radiometric slice.

## In scope

- Add helper for raw frame artifact registration.
- Add helper for radiometric processing output artifact registration.
- Add a small generic internal helper if useful.
- Use deterministic artifact ids:
  - `raw_frame`;
  - `radiometric.processing_frame` or the final id chosen by `AMNT-0037`.

## Out of scope

- No helpers for missing stages unless they are already needed by current code.
- No stage implementation.
- No profiling implementation.
- No result builder changes.

## User constraints

- Keep helpers limited to the current runtime.

## Source access rules

Canonical development. Legacy access is forbidden.

## Assumptions

- Raw frame parent is empty.
- Radiometric artifact parent is `raw_frame`.

## Result

Completed.

Added minimal artifact registration helpers to the existing `dp1v2` frame context helper boundary:

- `register_raw_frame_artifact(FrameContext &, const FramePacket &)` registers deterministic `raw_frame` metadata with `producer_stage = "input"`, Raw domain, `OwnedByFramePacket` ownership, source pixel metadata, bit depth, and geometry.
- `register_radiometric_processing_artifact(FrameContext &, const ProcessingFrame &)` registers deterministic `radiometric.processing_frame` metadata with `producer_stage = "radiometric_correction"`, Processing domain, `OwnedByStageOutput` ownership, parent `raw_frame`, output pixel format, inherited input bit depth, and output geometry.

Implemented duplicate id behavior as deterministic upsert in `datapro1_v2/src/frame/frame_context.cpp`: if an artifact id already exists, the helper replaces that record; otherwise it appends a new record. The helper boundary does not include `radiometric_stage.hpp` and does not store `cv::Mat`, pointers, references, owning handles, stage outputs, or profiling data in `FrameContext.artifacts`.

Validation performed:

- Built `datapro1_v2` with `cmake --build build-host-debug-full --target datapro1_v2`; build completed successfully. Existing warnings about `SingleFramePipelineResult::evidence_path` initializers remain unrelated to this task.

No Stage 0, TileScheduler, CameraProSim, missing stages, automated tests, result builder changes, AMNT-0042, or AMNT-0043 work was performed.
