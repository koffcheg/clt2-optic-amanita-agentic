## Summary

Add `prep.parameters.tiles.tile_count` as an alternative to explicit
`tile_width` / `tile_height` tile layout for `datapro1_v2`.

## Goal

Allow users to request a fixed number of tiles while `PrepStage` computes a
deterministic row-major grid from the normalized `CanonicalFrame.geometry`.

## In scope

- Extend `PrepTilesParametersConfig` with `std::optional<int> tile_count`.
- Parse and validate `tile_count` in the prep tiles configuration.
- Reject configs that combine `tile_count` with `tile_width` or `tile_height`.
- Calculate `tile_count` grids inside `PrepStage::process(PrepTilesInput, ...)`
  from `input.frame.geometry`.
- Keep explicit-size tile behavior backward compatible.
- Add focused unit tests for config parsing, grid selection, overlap handling,
  binned-canonical-frame geometry, and downstream contract safety.

## Out of scope

- Project Knowledge changes beyond this task card and `TASKS_INDEX.md`.
- `TilePipeline`, `TileExecutor`, `TileProcessor`, `TileFrameAggregator`,
  `RadiometricStage`, `TileRadiometricStateStore`, `FrameContext`, or
  `InputNormalizationStage` changes.
- New layout modes, user-facing row/column controls, auto-overlap, border
  policies, merge changes, or a separate tile layout resolver class.

## User constraints

- Do not touch Project Knowledge except this task card and the task index.
- Tests may be created or edited.
- Do not create a separate `TileLayoutResolver`.
- Do not change `TileDesc` or `TileRawView` semantics.
- Runtime tile-count layout must use `CanonicalFrame.geometry`, not source
  frame geometry or bin factors.

## Source access rules

Canonical development only. Legacy sources are forbidden for code generation.

## Assumptions

- Existing `PrepStage` tile route already creates correct `TileDesc` and
  `TileRawView` contracts for explicit-size layout.
- Existing tests under `tests/unit/dp1` are the correct place for focused
  unit coverage.

  `CanonicalFrame.geometry`.
- Accidental downstream contract drift for `TileDesc` or `TileRawView`.
- Regression in explicit-size tile layout.

## Result

Implemented `prep.parameters.tiles.tile_count` support:

- added `std::optional<int> tile_count` to `PrepTilesParametersConfig`;
- updated prep tiles parser validation for allowed key, integer type,
  positivity, and mutual exclusion with `tile_width` / `tile_height`;
- kept explicit-size tile config and layout behavior backward compatible;
- added in-`PrepStage` grid resolution from `input.frame.geometry`;
- added deterministic row-major tile-count layout with exact tile count;
- shared `TileDesc` / `TileRawView` construction for both layout modes;
- added runtime overlap checks against resolved tile-count core rectangles;
- added focused config and prep-stage unit coverage for square, wide, tall,
  overlap, binned `CanonicalFrame` geometry, invalid config, invalid runtime
  overlap, and downstream tile contract safety.
