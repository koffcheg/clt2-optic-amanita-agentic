## Summary

Implement typed resolved configuration for `prep.tiles` and create `PrepStage`
from `ResolvedPipelineConfig::prep`, matching the existing
`RadiometricResolvedConfig` model.

## Goal

`prep.tiles` parameters are validated during configuration loading and exposed
as typed `PrepTilesParametersConfig`, while `StageConfig prep` remains the source
for `enabled`, `variant`, and `level`.

## In scope

- Add `PrepTilesParametersConfig` and `PrepResolvedConfig`.
- Resolve `pipeline.pipeline.prep.parameters.tiles` into typed config.
- Reject unknown `prep` parameters for `full_frame`, `roi`, and `adaptive_roi`.
- Require explicit tile dimensions and overlap values for `tiles`.
- Construct `PrepStage` from `context.config.resolved_pipeline.prep`.
- Add unit coverage for valid and invalid config shapes.
- Add focused `PrepStage` tests for resolved-config capability behavior.
- Refactor radiometric runtime dispatch so `RadiometricStage` owns disabled and unsupported status decisions.

## Out of scope

- Implementing the tile slicing algorithm.
- Changing the runtime to execute the tiles route end to end.
- Domain Project Knowledge card updates.
- Broad runtime or pipeline refactoring.
- Legacy DP1 analysis or code reuse.

## User constraints

- Work as one task.
- `prep.tiles` should be typed config only in this slice.
- Tile algorithm implementation is deferred to a later task.

## Source access rules

Canonical development only. Legacy access is forbidden.

## Assumptions

- Current full-frame Prep behavior remains unchanged.
- `prep.tiles` invalid configuration must fail during config loading.
- If `PrepStage` receives a tiles request with missing resolved config, it returns
  `Failed` with a clear reason.
- If resolved tile config exists, the actual tile algorithm remains out of scope.
