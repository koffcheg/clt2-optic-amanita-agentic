## Summary

Update the canonical stage contract to require both explicit stage outputs and
`FrameContext` artifact reflection.

## Goal

Prevent both incorrect extremes:

- storing primary results only inside `FrameContext`;
- producing authoritative results outside `FrameContext` with no registry /
  provenance record.

## In scope

- Update `process(input, context, config) -> output` interpretation.
- Keep explicit output as mandatory.
- Add reflection rule for successful authoritative outputs.
- Define behavior for completed, failed, unsupported, skipped, and disabled
  stages at the contract level.
- State that reflection may be performed by the stage implementation or by
  pipeline orchestration, but the final effect is mandatory.

## Out of scope

- No code changes.
- No stage implementation.
- No stage signature changes.
- No new stage list.
- No Stage 0 or TileScheduler.

## User constraints

- Do not broaden to missing stages.
- Do not replace `StageOutcome<T>` with context-only output.

## Source access rules

Canonical development. Legacy access is forbidden.

## Assumptions

- The current stage interface shape remains useful.
- The problem is missing context reflection, not the existence of explicit
  outputs.

## Result

Completed.

Updated `dp1.pipeline.stage_contract` to require both explicit stage outputs
and `FrameContext.artifacts` reflection for successful authoritative outputs.
The contract now states that a stage must not store a primary result only in
`FrameContext`, and must not produce an authoritative result without an
artifact/provenance record in `FrameContext.artifacts`.

Added contract-level behavior for `completed`, `failed`, `unsupported`,
`skipped`, and `disabled` statuses. Failed, unsupported, skipped, and disabled
stages must not create fake output artifacts; they may record status or
diagnostics in `FrameContext`. Reflection may be performed by the stage
implementation or by pipeline orchestration, but the final effect is mandatory
for authoritative outputs.

Validation performed by documentation review against `AMNT-0034`, `AMNT-0035`,
`dp1.domain.runtime.frame_context`, and the AMNT-0036 scope. No code, tests,
Stage 0, TileScheduler, CameraProSim, missing stages, or AMNT-0037 work were
changed or created.
