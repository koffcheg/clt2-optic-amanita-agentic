# CODE_STYLE.md

## Призначення

Цей файл описує правила написання коду в проєкті.

Агент повинен використовувати цей файл як головне джерело coding conventions.
Якщо правило не визначене явно, агент повинен:
- не вигадувати нову локальну конвенцію;
- дотримуватися наявного стилю конкретного модуля;
- у разі сумніву описати варіанти і попросити узгодження.

## Статус документа

Статус: draft

Цей документ є шаблоном.
Частина правил може бути неузгодженою або неповною.
Поки правило не заповнене, агент не повинен вважати, що воно дозволяє довільне рішення.

## Загальні принципи

Агент повинен:
- надавати перевагу мінімальним і локальним змінам;
- зберігати стиль уже наявного коду в конкретному модулі;
- уникати змішування кількох стилів в одному файлі;
- не робити stylistic cleanup поза межами поточної задачі;
- не виконувати масове форматування без явного узгодження.

## Межі автоматичних змін

Без явного узгодження агенту заборонено:
- масово форматувати файли;
- змінювати naming conventions у великій кількості файлів;
- переносити код між модулями лише заради "кращої структури";
- змінювати стиль у файлах, які не входять до поточної задачі;
- замінювати існуючий стиль на інший лише через особисту перевагу.

## Коментарі та документація в коді

Тут потрібно визначити:
- коли коментар потрібен;
- коли коментар зайвий;
- якою мовою писати коментарі;
- чи потрібні doc-comments;
- як описувати non-obvious logic;
- як описувати assumptions і invariants.

Базове тимчасове правило:
Агент не повинен додавати коментарі, які лише повторюють очевидний код.
Коментарі слід додавати тільки там, де без них важко зрозуміти контракт, припущення, обмеження або нестандартну логіку.

## Рефакторинг

Без явного узгодження агент повинен:
- уникати широкого рефакторингу;
- не поєднувати функціональну зміну і stylistic cleanup в одному коміті/патчі;
- не змінювати структуру модулів без потреби;
- не переписувати стабільний код лише через інший preferred style.

## Робота з legacy-кодом

Якщо код у модулі не відповідає цьому документу, агент повинен:
- не виправляти весь файл автоматично;
- працювати локально в межах задачі;
- мінімізувати стильові побічні зміни;
- окремо позначати місця, де потрібна майбутня стандартизація.
