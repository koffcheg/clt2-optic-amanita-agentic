# ТЗ: Міжкадровий попіксельний медіанний фільтр

## 1. Призначення

Реалізувати модуль, який для відеопотоку обчислює міжкадрову попіксельну медіану лише по часу, без просторового вікна, та формує різницевий кадр для подальшої обробки в pipeline:

```text
R_t(x, y) = I_t(x, y) - Med_t(x, y)
```

де:

- `I_t(x, y)` - значення пікселя поточного кадру;
- `Med_t(x, y)` - міжкадрова медіанна оцінка фону для відповідного пікселя;
- `R_t(x, y)` - residual, тобто результат інверсної міжкадрової медіанної фільтрації.

Фільтр працює у потоковому режимі. Кадри надходять послідовно, а для обчислення медіани використовуються тільки поточний та попередні відібрані кадри. Майбутні кадри не використовуються.

## 2. Вхідні та вихідні дані

### 2.1. Вхід

- Вхідні кадри `I_t` розміру `N x M`.
- Формат зображення: один канал, grayscale.
- Тип пікселя: `uint8` або `uint16`.
- Кадри надходять послідовно у streaming-режимі.

### 2.2. Вихід

Модуль формує:

- `Med_t` - медіанний кадр, опційно для діагностики, логів або подальшого аналізу;
- `Residual_t` - різницевий кадр `I_t - Med_t`.

Медіанний кадр `Med_t` зберігається у тому самому форматі, що й вхідні кадри:

- для `uint8` вхідних кадрів - `uint8`;
- для `uint16` вхідних кадрів - `uint16`.

Якщо у вхідному потоці застосовується бінування, формат медіанного кадру повинен відповідати фактичному формату кадрів після бінування.

Residual формується у знаковому форматі підвищеної розрядності:

- для `uint8` вхідних кадрів - `int16`;
- для `uint16` вхідних кадрів - `int32`.

Підвищена розрядність потрібна тому, що операція обчислення residual може призводити до появи від'ємних значень та до розширення діапазону значень. Важливо: сам медіанний фільтр не розширює діапазон яскравості; розширення виникає саме на етапі віднімання `I_t - Med_t`.

## 3. Режими роботи

Підтримуються два режими:

1. `FixedK3` - точна міжкадрова медіана за 3 кадрами.
2. `FixedK5` - точна міжкадрова медіана за 5 кадрами.

Для обох режимів використовується однакова логіка часу:

- тільки каузальна обробка;
- медіана обчислюється за поточним та попередніми відібраними кадрами;
- медіана оновлюється тільки на відібраних кадрах;
- residual видається для кожного вхідного кадру з використанням останньої обчисленої медіани.

## 4. Параметри конфігурації

Основні параметри:

- `enabled` - ознака ввімкнення фільтра при старті програми;
- `mode` - режим обчислення медіани: `FixedK3` або `FixedK5`;
- `stride` - крок відбору кадрів у часове медіанне вікно, `stride >= 1`;
- `output_median_frame` - ознака формування/повернення медіанного кадру для діагностики;
- `output_dynamic_range_mode` - режим представлення residual на виході для користувача або зовнішніх модулів.

Рекомендована структура конфігурації:

```cpp
enum class TemporalMedianMode {
    FixedK3,
    FixedK5
};

enum class OutputDynamicRangeMode {
    RawSigned,
    ClipToInputRange,
    ShiftToPositive,
    ScaleToInputRange
};

struct TemporalMedianConfig {
    bool enabled = true;
    TemporalMedianMode mode = TemporalMedianMode::FixedK3;
    int stride = 1;
    bool output_median_frame = false;
    OutputDynamicRangeMode output_dynamic_range_mode =
        OutputDynamicRangeMode::RawSigned;
};
```

Якщо фільтр вимкнено у конфігурації при старті програми, пам'ять під циклічний буфер кадрів не виділяється.

Параметр `stride` може змінюватися під час роботи камери за командою контуру адаптації через конфігурацію.

## 5. Семантика stride

`stride` - це не крок пам'яті і не аналог OpenCV row stride. У цьому ТЗ `stride` означає крок часової дискретизації для формування медіанного вікна.

Кадр потрапляє у медіанний буфер, якщо він є кожним `stride`-м кадром потоку. Наприклад, якщо лічильник кадрів починається з 0, кадр відбирається за умовою:

```text
t % stride == 0
```

Приклади:

- `stride = 1` - у буфер потрапляє кожний кадр;
- `stride = 2` - у буфер потрапляє кожний другий кадр;
- `stride = 3` - у буфер потрапляє кожний третій кадр.

Для каузального вікна:

- `K = 3`, `stride = 2`: медіана на момент оновлення обчислюється за кадрами `t-4`, `t-2`, `t`;
- `K = 5`, `stride = 3`: медіана на момент оновлення обчислюється за кадрами `t-12`, `t-9`, `t-6`, `t-3`, `t`.

Мета використання `stride`:

- зменшення обчислювального навантаження;
- зменшення частоти оновлення оцінки фону;
- підвищення інерційності фону;
- зменшення впливу швидких рухомих об'єктів на медіанну оцінку.

## 6. Внутрішня логіка роботи

### 6.1. Лічильник кадрів

Модуль веде глобальний лічильник кадрів `t`. Початок відліку, з 0 або з 1, повинен бути явно зафіксований у реалізації та тестах.

Кадр додається у циклічний буфер медіани тільки тоді, коли він відповідає правилу відбору за `stride`.

### 6.2. Циклічний буфер

Для режиму `FixedK3` використовується циклічний буфер на 3 відібрані кадри.

Для режиму `FixedK5` використовується циклічний буфер на 5 відібраних кадрів.

Усі буфери повинні виділятися один раз у конструкторі або в методі `reset()`. Заборонено створювати нові масиви, `std::vector`, `cv::Mat` або інші динамічні об'єкти в гарячому циклі `processFrame`.

### 6.3. Оновлення медіани та формування residual

Медіана оновлюється тільки для кадрів, які потрапляють у медіанний буфер згідно зі `stride`.

Residual формується для кожного вхідного кадру. Якщо поточний кадр не потрапляє у медіанний буфер, для формування residual використовується остання обчислена медіана.

До заповнення циклічного буфера достатньою кількістю кадрів результат вважається невалідним. У цьому випадку `processFrame` повинен повертати ознаку відсутності валідного residual.

## 7. API та вимоги до реалізації

Допускається реалізація на сирих масивах або через `cv::Mat`. Незалежно від конкретного API необхідно забезпечити:

- окреме ядро для `FixedK3`;
- окреме ядро для `FixedK5`;
- вибір ядра один раз під час ініціалізації або в конструкторі;
- відсутність динамічних алокацій у `processFrame`;
- повторне використання всіх службових буферів;
- лінійну складність відносно кількості пікселів кадру.

Приклад інтерфейсу:

```cpp
class TemporalMedianFilter {
public:
    explicit TemporalMedianFilter(const TemporalMedianConfig& config);

    void reset(int width, int height, PixelType pixel_type);

    bool processFrame(
        const void* input_frame,
        void* residual_frame,
        void* median_frame_optional);
};
```

Конкретна сигнатура може бути змінена відповідно до архітектури проєкту, але вимоги до режимів, типів даних, буферів та відсутності алокацій у `processFrame` повинні зберігатися.

## 8. Ядра обчислення медіани

### 8.1. Ядро FixedK3

Для `K = 3` використовується піксельне ядро без повного сортування:

```cpp
template<typename T>
inline T median3(T a, T b, T c)
{
    if (a > b) std::swap(a, b);
    if (b > c) std::swap(b, c);
    if (a > b) std::swap(a, b);
    return b;
}
```

Для кожного пікселя беруться значення з трьох відібраних кадрів циклічного буфера, після чого обчислюється медіана через `median3`.

### 8.2. Ядро FixedK5

Для `K = 5` використовується фіксована sorting network на compare-swap операціях:

```cpp
template<typename T>
inline void cswap(T& x, T& y)
{
    if (x > y) std::swap(x, y);
}

template<typename T>
inline T median5(T a, T b, T c, T d, T e)
{
    cswap(a, b);
    cswap(d, e);
    cswap(c, e);
    cswap(c, d);
    cswap(a, d);
    cswap(b, e);
    cswap(b, c);
    cswap(a, c);
    cswap(b, d);
    return c;
}
```

Для кожного пікселя беруться значення з п'яти відібраних кадрів циклічного буфера, після чого обчислюється медіана через `median5`.

## 9. Обчислення residual

Після отримання `Med_t` residual обчислюється попіксельно:

```text
Residual_t[i] = I_t[i] - Med_t[i]
```

Для `uint8`:

```cpp
residual[i] = static_cast<int16_t>(cur[i]) -
              static_cast<int16_t>(med[i]);
```

Для `uint16`:

```cpp
residual[i] = static_cast<int32_t>(cur[i]) -
              static_cast<int32_t>(med[i]);
```

Residual у форматі `int16` або `int32` є основним внутрішнім представленням для pipeline, оскільки воно зберігає від'ємні значення та не втрачає інформацію через обмеження діапазону.

## 10. Приведення residual до вихідного формату

Оскільки результат інверсної медіанної фільтрації може мати розширений діапазон, для повернення результату користувачу, візуалізації, запису у файл або передачі у модулі, що очікують `uint8`/`uint16`, передбачається окремий етап приведення діапазону.

Підтримуються режими:

### 10.1. RawSigned

Residual повертається без приведення:

- `int16` для вхідного `uint8`;
- `int32` для вхідного `uint16`.

Цей режим рекомендований для внутрішніх обчислень pipeline та для задач, де важливо не втрачати слабкі сигнали.

### 10.2. ClipToInputRange

Значення residual обмежуються діапазоном вхідного формату:

- для `uint8`: `[0, 255]`;
- для `uint16`: `[0, 65535]`.

Цей режим є рекомендованим для користувацького виходу за замовчуванням, оскільки не змінює масштаб сигналу та зберігає локальний контраст у межах допустимого діапазону.

### 10.3. ShiftToPositive

Усі значення residual зсуваються у додатну область. Метод може бути корисним для візуалізації, але змінює базовий рівень сигналу.

### 10.4. ScaleToInputRange

Значення residual масштабуються до діапазону вхідного формату. Метод гарантує потрапляння в допустимий діапазон, але може зменшувати видимість слабкоконтрастних об'єктів.

## 11. Продуктивність та обмеження

Основні вимоги:

- заборонені динамічні алокації у гарячому циклі `processFrame`;
- усі буфери виділяються в конструкторі або `reset()`;
- час обробки масштабується лінійно від `N x M`;
- для `FixedK3` і `FixedK5` кількість операцій на піксель є фіксованою;
- час виконання медіанного ядра не залежить від статистики значень пікселів;
- аномальні пікселі можуть впливати на значення residual, але не повинні впливати на час виконання медіанного ядра.

Орієнтовна складність:

- `FixedK3`: 3 compare-swap операції на піксель;
- `FixedK5`: фіксована sorting network, приблизно 9 compare-swap операцій на піксель;
- residual: один прохід по кадру;
- приведення residual до вихідного формату: додатковий прохід по кадру.

Етап приведення формату має складність `O(N x M)` і додає окрему вартість:

- `ClipToInputRange`: приблизно 2-3 операції min/max на піксель;
- `ScaleToInputRange`: множення та приведення типу, дорожче за clipping;
- `ShiftToPositive`: може потребувати попереднього пошуку глобального мінімуму, тобто додаткового проходу по кадру.

Для high-FPS режимів рекомендовано виконувати приведення формату тільки тоді, коли це справді потрібно: при передачі результату користувачу, візуалізації, записі у файл або інтеграції з модулем, що очікує `uint8`/`uint16`.

## 12. Аномальні пікселі та розширення діапазону

У міжкадровому випадку аномальні пікселі можуть проявлятися як:

- тимчасові імпульсні завади;
- стабільні дефекти сенсора, зокрема гарячі або биті пікселі;
- короткочасні яскраві об'єкти.

Для малого вікна `K = 3` або `K = 5` медіана ефективно пригнічує одиничні імпульсні завади, але стабільні аномалії, які присутні у більшості кадрів вікна, можуть залишатися в оцінці фону.

У residual такі аномалії можуть призводити до:

- появи екстремальних додатних або від'ємних значень;
- розширення динамічного діапазону residual;
- збільшення кількості значень, які будуть обмежені при `ClipToInputRange`.

При цьому час виконання `FixedK3` та `FixedK5` залишається стабільним, оскільки алгоритм використовує фіксовану послідовність compare-swap операцій і не містить ітерацій, залежних від значень пікселів.

## 13. Граничні умови

До заповнення циклічного буфера достатньою кількістю відібраних кадрів результат residual не є валідним.

Очікувана поведінка:

- `processFrame` повертає `false`, якщо валідний residual ще не може бути сформований;
- після заповнення буфера `processFrame` повертає `true` для кожного вхідного кадру;
- медіана оновлюється тільки на кадрах, відібраних за `stride`;
- для проміжних кадрів використовується остання валідна медіана.

## 14. Юніт-тести

Необхідно реалізувати повільний еталонний алгоритм, який для кожного пікселя збирає значення з відповідного часового вікна та обчислює медіану через повне сортування. Результати швидких ядер повинні порівнюватися з еталоном.

Обов'язкові тести:

- `FixedK3`, `stride = 1`;
- `FixedK3`, `stride = 2`;
- `FixedK3`, `stride = 3`;
- `FixedK5`, `stride = 1`;
- `FixedK5`, `stride = 2`;
- `FixedK5`, `stride = 3`;
- перевірка каузального формування вікна;
- перевірка використання останньої медіани для кадрів, які не потрапили у буфер;
- перевірка поведінки до заповнення буфера;
- перевірка `Residual_t` для `uint8 -> int16`;
- перевірка `Residual_t` для `uint16 -> int32`;
- перевірка `RawSigned`;
- перевірка `ClipToInputRange`;
- перевірка `ShiftToPositive`;
- перевірка `ScaleToInputRange`;
- перевірка відсутності динамічних алокацій у `processFrame`, якщо це можливо інструментально.

Вимоги до коректності:

- побітова рівність `Med_t` з еталонною реалізацією;
- точна відповідність residual формулі `I_t - Med_t`;
- коректне обмеження значень при `ClipToInputRange`;
- стабільна робота на довгій послідовності кадрів без витоків пам'яті.

## 15. Приймальні критерії

Реалізація вважається прийнятою, якщо:

- підтримані режими `FixedK3` та `FixedK5`;
- підтримані типи вхідних кадрів `uint8` та `uint16`;
- медіанний кадр формується у форматі вхідного кадру;
- residual формується у `int16` або `int32` відповідно до типу входу;
- реалізовано змінний `stride`;
- residual видається для кожного кадру після заповнення буфера;
- для проміжних кадрів використовується остання обчислена медіана;
- відсутні алокації у `processFrame`;
- реалізовані режими приведення `RawSigned`, `ClipToInputRange`, `ShiftToPositive`, `ScaleToInputRange`;
- дефолтним режимом для внутрішнього pipeline є `RawSigned`;
- рекомендованим користувацьким режимом є `ClipToInputRange`;
- усі обов'язкові юніт-тести проходять успішно;
- час обробки масштабується лінійно від розміру кадру;
- час виконання медіанного ядра не залежить від статистики значень пікселів.
